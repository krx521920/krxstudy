# 测试环境排障：Linux命令、资源监控与远程终端

## 一句话解释与类比

**排障是把“页面不能用”逐层转换为可验证的假设，再用日志和指标缩小范围。**像医生检查：体温高是现象，需要结合其他证据，不能只看到 CPU 高就断定必须扩容。

Shell 是解释命令的程序，终端是与它交互的界面。基础见 [[CMD、Bash与PowerShell]]、[[Unix与Linux设计哲学：文件、小工具与管道]]。以下为 Linux 示例，不应直接当 PowerShell 命令运行。

## 一、先固定故障上下文

记录环境、构建版本、时区、账号、请求路径、请求 ID、操作和预期。确认是所有用户还是单个账号、持续还是偶发、最近是否发布或改配置。

先只读检查，保留日志。直接重启可能暂时恢复，但也会消除关键证据，并不能证明根因已修复。

## 二、日志、进程与接口

```bash
grep -n -i "error" app.log
tail -n 100 app.log
tail -f app.log
ps -ef
top
curl --max-time 5 -i http://127.0.0.1:8000/health
```

依次用于搜索错误行、看末尾日志、跟随追加、列进程、观察资源、检查本地练习服务响应。地址仅作示例，不代表已启动服务；持续命令通常可用 Ctrl+C 结束。

`grep` 命中的是文本，不是自动诊断；应看前后文和关联 ID。`tail -f` 在日志轮转后行为可能不满足需求，可了解 `tail -F` 的按文件名重试机制。`ps` 有进程只能证明它存在，`/health` 返回正常也不必然证明数据库、播放和订单正常。

systemd 环境还可用 `systemctl status 服务名` 和 `journalctl -u 服务名 --since "时间"` 查看对应服务；容器环境用 `docker ps`、`docker logs --tail 100 容器名`、`docker stats`。服务名和容器名需从自己的测试环境实际读取。

## 三、资源工具分别观察什么

| 工具 | 常见观察对象 | 解释注意点 |
|---|---|---|
| vmstat | 运行队列、内存、交换、I/O、CPU | 第一行常是启动以来统计，后续才是采样窗口 |
| iostat | CPU 和块设备吞吐、等待等 | 高利用率不能脱离设备并行能力判断饱和 |
| nmon | 多种系统资源的交互观察/采样 | 按平台和版本确认字段，先固定采样间隔 |
| iftop | 网络接口上按连接/主机显示流量 | 通常需要相应权限，不等于应用每个请求的耗时 |
| top | 进程资源与系统概况 | CPU 百分比受核心数和显示口径影响 |

例如 `vmstat 1 5` 每秒采样，共 5 次；`iostat -xz 1 5` 观察扩展磁盘统计。命令不存在时先确认发行版、包名和权限，不需要为看笔记就安装所有工具。

内存“空闲很少”可能是可回收缓存；容器 OOM 可能是额度先到而宿主仍有空闲。网络吞吐高可能是正常传输，磁盘等待也可能来自共享存储。把指标与故障时刻、业务负载对齐，才有解释价值。

## 四、一个具体排查例子

现象：课程详情间歇性超时。

1. 从测试客户端记录超时频率和请求 ID。
2. 入口日志确认请求是否到达、总耗时多少。
3. 应用日志定位停在缓存、数据库还是外部服务。
4. 如果数据库等待长，检查慢查询、连接池和锁；如果连接前就慢，检查 DNS/网络/TLS。
5. 对照同时间资源曲线，形成“某查询锁等待导致排队”的假设。
6. 在隔离环境用相同条件复现，验证修改后的行为，而不是只观察重启后暂时变快。

这是一条推理顺序，不保证每次都从同一层出问题。参见 [[SQL索引、执行计划与性能优化]]、[[TLS与数字证书]]、[[OOM：内存不足、显存不足与内存泄漏]]。

## 五、FinalShell、Xshell 和 SSH

SSH = Secure Shell，安全远程登录协议，逐字母读 S-S-H。FinalShell、Xshell 是提供远程终端/连接管理等能力的客户端；它们不是 Linux 系统，也不提供服务器本身。

基本连接需要主机、端口、账号和获准使用的认证方式。首次连接核对主机指纹；不要随便接受发生变化的指纹，也不要把密码写进共享笔记。客户端中的标签、文件面板和监控能力属于产品界面，权限仍由远端决定。

Windows 自带的 SSH 客户端也能连接服务器。选择图形客户端主要是操作体验和管理需要，不能认为装了 Xshell 就有权进入某台服务器。

## 六、部署验证与 Shell 脚本

部署一般包括：取得明确版本 → 准备配置和依赖 → 启动 → 检查日志与健康 → 业务冒烟 → 记录版本和回滚方式。Docker 把应用环境组织成镜像/容器，网络、数据卷、凭据和资源限制仍需配置。

Shell 脚本是把命令和控制逻辑写进文件。脚本应检查退出状态，区分“命令执行完”与“业务通过”，避免一行失败后继续部署。不要把复制来的删除或数据库命令当成只读排查命令。

练习先在本地虚拟机/容器制造一个“文件不存在”错误，寻找其时间与日志，再做简单健康查询。本次未连接任何服务器。
