# 持续集成测试：Jenkins、GitLab CI与版本回滚

## 一句话解释与类比

**持续集成把重复的构建和检查变成按规则触发的流水线，让每个版本留下可追溯的证据。**像工厂检验线：来一批零件就按同样流程检测，但检验项目设计不好，自动化只会更快地漏检。

CI = Continuous Integration，持续集成，读 C-I。CD 可指 Continuous Delivery（持续交付，保持可发布）或 Continuous Deployment（持续部署，通过后自动部署）；二者对上线动作的自动程度不同。

## 一、Git、GitLab、Jenkins、SVN 分别是什么

| 名称 | 角色 |
|---|---|
| Git | 分布式版本控制工具，记录提交和分支 |
| GitLab | 围绕 Git 的协作平台，提供仓库、合并请求、CI/CD 等能力，可有托管或自建形态 |
| Jenkins | 可配置的自动化服务，使用流水线和执行节点组织构建、测试等任务 |
| SVN/Subversion | 集中式版本控制系统，工作副本与中央仓库协作；不是 GitLab 的旧名称 |

Git 的本地提交不等于已经推送，也不等于流水线通过。SVN 的集中式修订模型与 Git 的本地提交/分布式历史不同，但都需要理解冲突、版本和协作。

## 二、一条测试流水线怎样运行

```mermaid
flowchart LR
    A[提交/合并请求/定时触发] --> B[检出明确提交]
    B --> C[按锁定依赖准备环境]
    C --> D[静态检查和单元测试]
    D --> E[接口和集成测试]
    E --> F[关键端到端检查]
    F --> G[收集报告与制品]
    G --> H[发布门禁与后续部署]
```

Runner/Agent 是实际执行任务的工作节点；流水线配置描述“做什么”，节点提供 CPU、依赖和网络。失败可能来自代码、测试、依赖下载或节点故障，要分类处理。

短检查适合每次提交；较长的浏览器、移动设备或性能任务可按风险在合并前、夜间或发布前运行。不能只因定时任务通过，就推断后来一个新提交也通过。

## 三、Jenkinsfile 与 GitLab 配置

Jenkins 常用仓库里的 `Jenkinsfile` 描述阶段；GitLab 常用 `.gitlab-ci.yml`，由 Runner 领取 Job。两者都可把配置纳入版本控制。

下面是已有测试工程的 GitLab 示意配置，要求测试执行节点已具备指定 Python 环境和项目依赖：

```yaml
stages: [test]
unit_tests:
  stage: test
  script:
    - python -m pytest tests/unit --junitxml=report.xml
  artifacts:
    when: always
    reports:
      junit: report.xml
```

它运行单元测试并尽量保存报告，没有配置部署，也不是完整生产模板。真实项目还需要明确执行器、依赖锁定、缓存策略、超时和权限。

缓存用于复用下载/构建数据；Artifact（制品）用于保留本次运行产生的报告、安装包或镜像信息。缓存命中不能替代可复现依赖，制品也不能混入访问密钥。

## 四、怎样让失败真的阻止不合格版本进入下一步

测试进程失败应返回非零退出码；不要在每个命令后加“忽略错误”。区分失败、跳过、未发现测试和报告未生成；没有执行任何用例也可能命令结束，必须核对发现数量和配置。

报告应关联提交 SHA、构建编号、环境、数据版本和执行日志。失败通知指向这些证据，不仅发“失败了”。仓库保护规则可以要求关键检查通过，但要确认检查对应当前待合并版本。

凭据存平台密钥管理设施，限制到必要任务；来自不可信分支的脚本不应自动拿到生产密钥。日志掩码不保证任何加工后的秘密都能被隐藏。

## 五、精准测试与并行加速

精准测试按改动和依赖影响选用例。依据可以是模块依赖、覆盖关系、历史失败和业务风险。改一个公共鉴权组件可能影响大量页面，不能只选同目录用例。

节省时间有三条路线：减少重复构建、并行运行独立用例、选择适当范围。并行前要隔离端口、账号、数据库和文件；分片全部结束并汇总，才能说整套完成。

精选用例需要定期较广回归和抽查来发现漏选；测试选择模型失效时应扩大范围。追求速度不能静默跳过高风险检查。

## 六、冲突、回滚和数据库兼容

Git 冲突处理：理解双方意图 → 修改成正确的合并结果 → 检查差异 → 运行相关验证 → 提交。删掉冲突标记只解决语法，不自动解决语义。

发布回滚需要明确的旧制品、配置与数据库兼容。代码回到旧版本，数据库新字段、已经发出的消息、已完成交易仍可能存在；不能把 Git 回退直接等同于业务恢复。

## 学习建议与常见误区

先在练习项目自动运行一条确定性测试，再加入报告、失败退出和分支触发，最后扩展环境与部署。Jenkins 安装成功不等于 CI 建成，流水线绿色也不等于生产所有业务已验收。
