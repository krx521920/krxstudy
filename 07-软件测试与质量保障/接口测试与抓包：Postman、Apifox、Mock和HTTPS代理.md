# 接口测试与抓包：Postman、Apifox、Mock和HTTPS代理

## 一句话解释与类比

**接口测试绕过页面，直接检查软件之间的请求和结果；抓包则观察实际通信经过了什么。**像检查外卖：页面是点餐窗口，接口是传给厨房的订单；收到“已接单”不代表菜品、价格和收货人都正确。

API（Application Programming Interface，应用程序编程接口，逐字母读 A-P-I）基础见 [[SDK与API]]；HTTP、HTTPS 见 [[TCP、HTTP、HTTPS与WebSocket]]。

## 一、请求里到底有什么

```http
GET /api/courses/42 HTTP/1.1
Host: 127.0.0.1:8000
Authorization: Bearer TEST_TOKEN
Accept: application/json
```

这是教学报文，不是已经存在的接口。方法表示动作，路径确定资源，头部携带认证和内容协商信息；查询参数在 URL 中，请求体则常见于创建/修改请求。`TEST_TOKEN` 是占位符。

JSON（JavaScript Object Notation，JavaScript 对象表示法，常读“杰森”）可以表达对象、数组、字符串、数字和空值。字符串 `"42"` 与数字 `42` 可能违反不同类型约束，不能只看视觉上相同。

## 二、断言：自动判断是否符合预期

“断言”就是写出一个必须成立的条件。接口验证至少分四层：

| 层 | 例子 | 单独通过仍不够的原因 |
|---|---|---|
| 通信/状态 | 是否超时，HTTP 状态码是否符合契约 | 200 中可能包含业务失败 |
| 结构 | 必需字段、类型、数组格式 | 字段都有，值也可能错 |
| 业务语义 | 课程编号、价格、权限是否正确 | 响应说成功，后台可能没落库 |
| 最终状态 | 数据库记录、库存、消息或模拟账本 | 页面可能仍展示旧缓存 |

HTTP 400 泛指请求问题，不只是“参数错”；401 通常表示缺失/无效认证，403 表示拒绝执行，404 也可能用于隐藏资源存在性；500 是服务端内部错误。依据接口契约断言，不能用固定口诀覆盖所有设计。

## 三、用例怎样组织

以创建课程报名为例：合法参数、缺字段、空值、类型错误、长度/数值边界、不存在的课程、无权用户、重复报名、并发重复、超时重试、过期登录、服务依赖异常。

对金额、资格和归属权，应校验服务端是否重新判断。前端禁用了按钮，并不保证直接调用接口的人不能绕过。

接口响应正确但界面错，常指向渲染、缓存或状态管理；没看到请求，也可能是缓存命中、前置校验、代理或抓取范围不对。定位链只是排查线索，不是凭一次观察判定责任的规则。

## 四、Postman 的最小操作路径

Postman 是 API 开发与测试工具。常见对象：Request（单次请求）、Collection（一组请求）、Environment（环境变量集合）和执行报告。

1. 建立一个练习集合和本地测试环境，设置 `base_url`。
2. 新建请求，填方法、`{{base_url}}/api/courses/42`、头部和必要参数。
3. 发送后检查状态、响应体、耗时；先确认契约，再添加断言。
4. 将登录结果中的测试令牌保存为环境变量，后续请求引用它。
5. 用不同账号和数据运行集合，保留每条断言结果。

以下脚本适用于约定返回 `{ "id": 42, "published": true }` 的教学接口：

```javascript
pm.test("状态与课程内容符合预期", function () {
  pm.response.to.have.status(200);
  const course = pm.response.json();
  pm.expect(course.id).to.eql(42);
  pm.expect(course.published).to.eql(true);
});
```

它同时验证状态和两条业务事实，不是只检查能否解析 JSON。真实用例还应验证权限、错误情况和相关数据变化。

**接口关联**例：登录 → 提取令牌 → 创建测试订单 → 提取订单 ID → 查询此订单 → 清理专属测试数据。不要硬编码上一轮订单，也不要把同一个可变环境变量供所有并行用户共享。

## 五、Apifox、Apipost、SoapUI 怎么理解

| 工具 | 核心用途 | 适合练习的事情 |
|---|---|---|
| Apifox | 接口设计、文档、调试、测试与 Mock 等协作 | 先定义字段与示例，再调试并验证实际响应 |
| Apipost | API 文档、调试与测试协作 | 管理环境、保存请求、串联业务请求 |
| SoapUI | Web 服务测试，支持 SOAP 和 REST 等 | 导入服务描述、组织请求、断言及模拟响应 |

SOAP 是基于 XML 消息的协议体系，WSDL（Web Services Description Language，Web 服务描述语言）描述服务契约。SOAP 不是“所有老接口”的同义词；SoapUI 也不仅能测试 SOAP。REST（Representational State Transfer，表述性状态转移，读“瑞斯特”）是一种架构风格，不是所有 JSON 接口的正式名称。

学习一种工具后，方法、参数、鉴权、断言、关联等知识可以迁移；脚本 API、变量作用域和运行器格式未必可以直接复制。

## 六、Mock 怎样帮助测试

Mock（读“莫克”）用可控制的替代对象模拟依赖行为。例：本地替代配送服务，分别返回“接受”“拒绝”“超时”“字段缺失”，观察订单系统的反应。

```text
被测订单服务 → 可控模拟配送服务
               ├─ 正常返回单号
               ├─ 返回业务拒绝
               ├─ 延迟超过约定超时
               └─ 返回格式异常
```

模拟响应可以让异常稳定复现，但不能证明真实第三方的签名、网络、限流和业务规则都兼容。还要保留真实契约测试或受控集成测试。Mock、Stub、Fake 在不同框架中叫法有差异，应说明替代了什么、检验了什么。

超时不等于对方没有执行。涉及写操作，应验证请求是否已生效、重试是否使用同一幂等键，见 [[状态机与幂等性]]。

## 七、Fiddler、Charles 与 HTTPS 抓包

Fiddler 和 Charles 是调试代理类工具，可观察经过它们的 HTTP 流量；按产品和版本还可提供规则改写、断点、限速等能力。Fiddler Classic 与 Everywhere 不是完全相同的产品界面。

HTTPS 下直接监听网络通常只能看到加密数据。解密代理的典型结构是：

```text
测试客户端 ←TLS连接A→ 调试代理 ←TLS连接B→ 真正服务
```

客户端需信任代理使用的证书颁发机构，代理再单独验证服务证书。证书固定、应用信任策略、双向 TLS、HTTP/3 或不遵守系统代理的流量都可能影响抓取，不能认为“装一张证书就一定抓到全部”。

只在授权测试设备上配置代理信任，使用隔离测试账号；结束后按需要撤销测试信任与代理设置。不要把关闭服务端证书校验作为生产修复办法。原理见 [[TLS与数字证书]]、[[系统代理、VPN与端口]]。

### 一次抓包排查的顺序

确认设备与代理连通 → 限定应用/域名 → 复现操作 → 用请求 ID 和时间关联 → 比对参数、响应与后台日志 → 最小化复现 → 恢复设置。

断点改包是把授权练习请求中的“商品价格 100”改为“1”，验证服务器是否依权威价格重新计算；预期是拒绝非法参数或忽略不可信价格。不能把“前端不让填”当成后台安全措施。

弱网测试分别设置带宽、延迟、抖动、丢包和断线；限速与丢包不是同一件事，不是每款 HTTP 代理都能真实模拟全部网络层故障。

## 常见误区与学习建议

发送成功不等于业务成功；截图里有 200 不等于测试通过；Mock 通过不等于真实集成通过；抓包没看到不等于请求没发。

先用一条只读查询练习请求与断言，再做登录关联，最后在模拟业务中加入异常和重复操作。自动化见 [[Python接口自动化：Requests、pytest、unittest与Allure]]；专项见 [[安全测试基础：越权、注入、XSS与扫描工具]]。
