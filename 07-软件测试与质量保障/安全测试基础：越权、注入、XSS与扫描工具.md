# 安全测试基础：越权、注入、XSS与扫描工具

## 一句话解释与类比

**安全测试验证系统能否在不可信输入和不允许的操作面前守住数据与权限边界。**像门禁检查：不仅检查有钥匙的人能进，还检查钥匙过期、串门、伪造身份和从侧门进入时是否被正确阻止。

练习使用自己控制或明确获准的测试环境、虚构账号与数据。本篇提供原理和防护验证方法，没有运行扫描、尝试真实账号或攻击外部站点。

## 一、认证与授权不能混为一谈

认证回答“你是谁”，授权回答“你能对哪个对象做什么”。登录成功的用户也可能无权读取某门课程或修改别人的订单。基础见 [[身份认证与授权：ACL、RBAC、MFA、OAuth、OIDC、SAML与SCIM]]。

**水平越权**：同一权限等级的账号访问不属于自己的对象。**垂直越权**：普通角色执行管理员等更高权限的动作。资源 ID 难猜可以减少偶然碰撞，但不能替代服务端授权。

### 一张可执行的权限测试矩阵

| 测试身份 | 自己的订单 | 同角色另一测试账号的订单 | 管理功能 |
|---|---|---|---|
| 未登录 | 按规则拒绝 | 拒绝 | 拒绝 |
| 用户 A | 允许自己的适用操作 | 拒绝读取/修改 | 拒绝 |
| 用户 B | 允许自己的适用操作 | 拒绝读取/修改 | 拒绝 |
| 授权管理员 | 按管理范围允许并审计 | 按管理范围允许并审计 | 按具体权限允许 |

测试时只使用事先创建的 A/B 测试对象，分别验证详情、列表、导出、修改、删除和批量接口。接口拒绝后还要检查数据没有改变，错误信息也不应泄露不必要的对象详情。

## 二、SQL 注入为什么发生

如果程序把输入拼到 SQL 语句结构中，用户数据可能被解释为查询语法。正确做法通常是参数化查询，把“语句”和“数据”分开，再结合最小权限。

以 Python SQLite 的安全查询形式为例：

```python
row = connection.execute(
    "SELECT id FROM users WHERE name = ?",
    (user_name,),
).fetchone()
```

`connection` 是已连接的练习数据库；问号是参数位置，用户输入作为独立值绑定。不同驱动占位符不同，不能把 `?` 原样用于所有数据库。

授权测试可使用包含引号、长文本和类型异常的虚构输入，检查被当作数据处理、不会扩大结果或改变数据库，并结合代码审查确认参数绑定。黑名单过滤几个字符不足以证明无注入；表名/排序字段等结构性选择需要白名单，不能总用值占位符代替。

## 三、XSS 与前端渲染

XSS = Cross-Site Scripting，跨站脚本，逐字母读 X-S-S。应用将不可信内容放入可执行的网页上下文，可能让恶意脚本在用户浏览器中运行。常见讨论包括反射型、存储型和基于 DOM 的问题。

测试目标是证明评论、昵称、搜索词等只以预期形式呈现。可先在本地页面使用 `<b>demo</b>` 等无害标记观察是文字还是 HTML，再检查模板转义、富文本清洗、属性和 URL 上下文；仅看到一个标记显示正常，不能证明所有上下文安全。

一般文本优先使用安全文本输出；允许富文本时使用可靠清洗机制；CSP（Content Security Policy，内容安全策略）提供额外限制。HttpOnly Cookie 减少脚本直接读 Cookie 的风险，却不能消除脚本在用户会话内发起操作的能力。

## 四、防暴力破解、会话和异常路径

- 错误登录是否受速率限制，提示是否暴露账号存在性。
- 锁定/解锁设计是否让别人轻易锁死合法用户。
- 退出、改密码、撤权后旧会话和刷新令牌是否按规则失效。
- 权限服务超时是否错误放行；缓存的权限过期如何处理。
- 上传、导出、搜索和后台任务是否使用同样的权限边界。

速率限制测试在小规模受控数据上进行，避免真实账号锁定。验证码出现也不证明后台所有接口都已被保护。

## 五、扫描工具、渗透测试与代码检查

| 名称 | 定位 | 输出怎样使用 |
|---|---|---|
| AppScan | 应用安全测试产品家族，具体产品覆盖能力不同 | 核对扫描类型、发现位置和验证证据 |
| AWVS/Acunetix | 常见于旧资料的 Web 漏洞扫描产品称呼；当前产品品牌按官方说明核对 | 不把扫描器报告直接等同真实可利用性 |
| SQLMap | 自动化检测 SQL 注入等能力的工具 | 在明确授权范围验证，控制动作与副作用 |

DAST = Dynamic Application Security Testing，动态应用安全测试，检查运行中的应用；SAST = Static Application Security Testing，静态应用安全测试，分析代码等静态材料。渗透测试还包括人工推理业务逻辑、验证风险与形成修复建议，不能等同“跑一次扫描”。

扫描前确认目标、账号、速率、时间窗口、禁止动作和数据恢复安排。登录流程没配置好时，工具可能只扫了登录页；未发现漏洞不证明所有受保护页面都测过。错误报告需复核，业务越权也不能只靠通用扫描发现。

## 六、修复验收如何闭环

重现原始失败 → 检查修复版本 → 验证原问题 → 验证合法功能仍可用 → 检查相似接口 → 记录范围与剩余问题。测试报告保留最少必要的脱敏证据。
