# 体验与兼容性测试：无障碍、适老化、国际化和文档

## 一句话解释与类比

**功能正确只是基础，体验与兼容性测试还要检查不同使用者能否在自己的环境里顺利完成目标。**像一扇门：能打开不代表坐轮椅的人、视力较弱的人或第一次来的人都方便通过。

UI = User Interface，用户界面，读 U-I；UX = User Experience，用户体验，读 U-X。界面检查偏向布局、元素和交互状态，易用性关注完成任务的有效性与效率，体验还包括信任、理解和整体感受。

## 一、怎样避免只凭“我觉得好用”

先写任务：让首次使用者找到今晚课程并进入直播。记录任务完成率、耗时、错误、求助次数和反馈；参与者应接近目标用户，不能全部由熟悉系统的开发人员代替。

教学例：5 人中 4 人找到课程，不意味着产品整体 80% 好用；样本小、用户类型和任务有限。观察可以发现具体阻碍，例如按钮名称不明确，再用后续测试验证修改。

## 二、界面测试的基本状态

| 状态 | 检查内容 |
|---|---|
| 正常/空数据 | 内容完整，空态说明下一步 |
| 加载/慢响应 | 有可理解反馈，避免重复提交 |
| 错误/恢复 | 原因和重试入口明确，已填内容尽量保留 |
| 禁用/无权限 | 能说明限制，后台权限仍独立生效 |
| 长文本/放大 | 不遮挡关键动作，不截断必要信息 |

颜色、字体和间距要依据设计与可用性标准，而不是测试者个人偏好。视觉截图差异也可能来自时间、字体和动态内容，应先稳定环境。

## 三、兼容性矩阵

维度包括浏览器/版本、操作系统、设备和屏幕、输入方式、字体、语言、网络和辅助技术。按用户占比、支持承诺及高风险功能选组合，可使用 [[测试用例设计：等价类、边界值、判定表与状态迁移]] 中的组合方法。

响应式页面宽度正常，不证明触摸、软键盘、横竖屏和 WebView 也正常。兼容性的目标是核心任务可完成，不一定要求所有平台像素完全一致。

## 四、无障碍怎样开始检查

无障碍关注不同能力的使用者能否感知、操作和理解内容。WCAG = Web Content Accessibility Guidelines，Web 内容无障碍指南，逐字母读 W-C-A-G。它提供可评估的要求，不能只用自动扫描分数替代人工检查。

初学检查可从以下任务开始：

1. 只用键盘 Tab、Shift+Tab、Enter 等能否完成登录，焦点是否可见、顺序是否合理。
2. 表单有没有可读标签，错误能否定位到对应字段。
3. 放大页面和调整文字后是否仍能操作。
4. 信息是否仅用颜色表达，必要图像是否有合适文字替代。
5. 用屏幕阅读器读取标题、按钮和动态反馈，确认名称与含义。
6. 视频是否具备适当字幕/文本等替代方式，弹窗焦点能否正确进入并返回。

工具能发现部分结构、对比度等问题，真实任务和辅助技术操作仍需要人工。网页使用原生语义元素通常更容易提供正确行为，见 [[HTML]]、[[CSS]]。

## 五、适老化不等于把字号调大

应一起考虑可辨识文字、足够触控空间、清晰返回路径、误触恢复、重要操作确认、短而准确的说明和可理解的错误。验证长辈常见任务，而不是假定所有老年用户需求相同。

教学场景：讲师开播通知后，用户能否清楚分辨“报名成功”和“正在直播”；退出后能否返回；音量/字幕是否容易找到。涉及付款的确认应显示真实对象和金额，不能靠诱导性颜色催促操作。

## 六、国际化与本地化

Internationalization（国际化）常写 i18n，18 表示首尾字母间的数量；Localization（本地化）常写 l10n。前者让系统具备适配不同地区的能力，后者完成某地区的实际语言和规则适配。

| 检查 | 可能问题 |
|---|---|
| 翻译长度与字符 | 按钮溢出、中文/表情损坏、占位符漏替换 |
| 日期与时区 | “11/12”歧义、跨日课程、夏令时 |
| 数字和货币 | 千位/小数分隔不同；换货币符号不等于完成换算 |
| 排序与搜索 | 大小写、重音、语言排序与分词差异 |
| 从右到左布局 | 方向、图标、混合数字文本排列 |
| 文案与规则 | 翻译字面正确但操作含义不清楚 |

字符串长度应明确按字节、码点还是用户感知字符计数。后台统一时间存储和前端地区展示是不同层，不能把“换语言”当成“换时区”。

## 七、文档测试

让没参与开发的人按帮助文档操作：前置依赖是否写全、截图是否对应版本、命令能否按步骤完成、错误说明是否准确。接口示例需匹配字段和鉴权规则，不能复制旧版本成功截图。

文档还要说明限制与恢复方式，例如“下载可续传”应实际验证中断后恢复，而不是只在说明书里出现这句话。

## 学习建议与关联

用一条“登录—找课程—观看”路径，分别用鼠标、键盘、小屏和放大模式检查，记录可复现阻碍。然后增加一种语言和一种辅助技术。移动场景见 [[移动端测试：ADB、日志、Monkey与性能诊断]]；报告见 [[测试流程与缺陷管理：从需求评审到发布报告]]。
