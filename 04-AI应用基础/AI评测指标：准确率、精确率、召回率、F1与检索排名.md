# AI评测指标：准确率、精确率、召回率、F1与检索排名

## 一句话解释与类比

**评测指标是按明确口径把表现变成数字；不同指标回答不同问题，不能只看一个总分。**像筛选坏苹果：挑出来的是否真坏，与所有坏苹果有没有找全，是两件事。

AI = Artificial Intelligence，人工智能，读 A-I。以下数字均为教学计算，不是某款模型的实测成绩。

## 一、先约定“正类”，再画混淆矩阵

以“识别需要转人工的问题”为例，正类是确实需要转人工的问题。有 100 条问题，其中 10 条需要转人工；模型判定 20 条要转人工，其中 8 条判断正确。

|  | 实际需要转人工 | 实际不需要 |
|---|---:|---:|
| 模型判需要 | 8，TP | 12，FP |
| 模型判不需要 | 2，FN | 78，TN |

- TP = True Positive，真正例：该转，也转了。
- FP = False Positive，假正例：不该转，却转了。
- FN = False Negative，假负例：该转，却漏了。
- TN = True Negative，真负例：不该转，也没转。

这些缩写逐字母读。正类换成“允许回答”时，含义也随之改变，不能只背字母。

## 二、四个指标逐个手算

| 指标 | 公式 | 上例结果 | 主要问题 |
|---|---|---:|---|
| Accuracy，准确率 | (TP+TN)/全部 | 86/100=86% | 总体判对多少？ |
| Precision，精确率 | TP/(TP+FP) | 8/20=40% | 判为正类的有多少是真的？ |
| Recall，召回率 | TP/(TP+FN) | 8/10=80% | 所有真实正类找到了多少？ |
| F1 | 2PR/(P+R) | 约53.3% | 精确率与召回率的调和平均 |

这里 P 代表 Precision，R 代表 Recall。F1 不是准确率与召回率的平均；也不是简单算术平均。分母为零时如何处理，应按评测协议和工具设置明确报告。

如果模型把 100 条全部判成“不需要”，准确率仍有 90%，但真正需要转人工的全漏了。类别不平衡时，整体准确率会掩盖关键失败。

阈值放宽可能提高召回却增加误报；阈值收紧可能提高精确率却漏掉目标。支付风控、内容推荐和客服分流的错误代价不同，不能统一追求某个指标最大。

## 三、多分类、Macro 与 Micro

意图分类可能包含咨询课程、退课、投诉等多个类别。可以先逐类做“一类对其他类”的统计。

- Macro 平均：先算每一类指标再等权平均，容易看到小类别表现。
- Micro 平均：汇总各类 TP/FP/FN 再计算，结果更受样本多的类别影响。
- Weighted 平均：按各类样本量加权；也可能掩盖小类失败。

报告时保留每一类样本量和结果。仅写“F1=0.9”，却不说明正类、平均方式、阈值和评测集，信息不足。

## 四、检索中的 Precision@K 与 Recall@K

K 表示只看排名前 K 条。假设某问题共有 5 份标注相关资料，检索前 3 条中有 2 份相关：

- Precision@3 = 2/3：取回的前 3 条有多干净。
- Recall@3 = 2/5：所有应找到的相关资料找回多少。
- Hit@3 = 1：前 3 条至少找到一份相关资料，这次查询算命中。

**Hit Rate@K（命中率）**通常在多条查询上统计“至少命中一项”的比例；不能一般性地等同 Recall@K。只有每个查询恰好一个相关目标等特定设定下，两者可能一致。

要先定义相关对象是整篇文档、片段还是事实。一个事实被拆成 3 个重复片段，不应随意让指标看起来提高。没有相关答案的问题需要单独评估拒答，不能硬给 Recall 分母填一个数。

## 五、MRR：第一个有用结果有多靠前

MRR = Mean Reciprocal Rank，平均倒数排名，读 M-R-R。对每条查询，找到第一个相关结果的排名 r，记 1/r；范围内完全没找到则记 0，最后平均。

三个查询的第一条相关结果分别排第 1、第 2、未找到：

```text
MRR = (1 + 1/2 + 0) / 3 = 0.5
```

MRR 偏向“用户很快找到一个有效结果”的场景，不能表示所有相关资料都找全，也不直接评价第一个相关结果之后的完整排序。若只看前 K 条，应明确写 MRR@K 或说明截断规则。

已有 [[BM25、关键词检索与混合检索]] 讲 BM25、RRF 和重排序：它们用于产生或融合排名；这里的指标用于评判排名，两者职责不同。

## 六、生成答案不能只用分类准确率

开放问题可能有多种正确表达。逐字符匹配适合固定答案或结构化字段，不能普遍用于自然语言解释。

| 维度 | 具体判断 |
|---|---|
| 事实正确性 | 与可靠事实是否一致 |
| 忠实度 Faithfulness | 答案中的事实主张能否由给定资料支持 |
| 相关性 | 是否回答用户的问题 |
| 完整性 | 关键部分是否遗漏 |
| 格式/约束 | 必需字段、类型和业务边界是否满足 |
| 引用 | 引用内容是否真的支持对应说法 |

资料自身过期时，回答可能忠实于资料却不符合当前事实；反过来，模型凭记忆答对，也不代表引用可靠。

**幻觉率**需要先定义单位：是含不支持主张的回答比例，还是所有可核验主张中的错误比例？两种分母不同。标注“未知/争议”并制定复核规则，比强行把每个答案归成对错更可靠。

## 七、怎样公平比较两个版本

固定数据集、标签、模型/提示配置、检索库版本和指标口径；记录每题结果，再比较整体及各切片。随机生成任务可运行多次，保留分布，而不只选最好的一次。

不要把开发中反复调过的题目全部当作独立验收集。数据量少时给出样本数和不确定性；一次 9/10 不能证明长期正确率恰好 90%。

评估器自身也会错。模型裁判需要人工校准和重复性检查，详见 [[Agent评测：上下文成本、轨迹与独立验收]]；RAG 分层见 [[RAG、Naive RAG与GraphRAG]]。

## 学习建议

先手算本篇的 100 条分类例子，再给自己的 5 个知识库问题标注相关文档，分别算 Precision@K、Recall@K 和 MRR。只有明确分母，才不会把“召回高”“准确率高”当成同一句话。
