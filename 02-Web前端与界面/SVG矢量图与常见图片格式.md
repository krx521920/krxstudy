# SVG矢量图与常见图片格式

## 一句话解释

**SVG 是一种用圆、直线、曲线、文字等描述画面的图形格式，特别适合图标、标志和图表；其中的矢量图形可以按新尺寸重新绘制，不必把原来的像素硬拉大。**

SVG 全称 **Scalable Vector Graphics（可缩放矢量图形）**，读作三个字母 S-V-G，文件名通常以 `.svg` 结尾。

它既是一种图形格式，也是一种描述图形的标记语言；不是一种图片编辑软件。[参考：MDN SVG 概述](https://developer.mozilla.org/en-US/docs/Web/SVG)

## 一、用“马赛克”和“画图说明书”理解

假设想保存一个蓝色圆形，有两种不同思路。

### 位图：记下每个小格子的颜色

把图片想成很多小格子组成的马赛克，每个格子就是一个像素。

位图，也叫光栅图，表示的是像素网格。文件会使用压缩等方式保存这些信息，不一定真的逐个原样写下每个像素。

把小图片大幅放大时，软件可以插值，让边缘过渡更平滑，但原文件没有的真实细节不会因此自动出现。

### 矢量图：记下“怎么画”

对于这个圆，SVG 可以描述：

> 在某个位置画一个圆，半径是多少，内部填蓝色，边框用什么颜色。

要显示得更大，就按照这些几何描述重新画一个更大的圆，不需要放大一张固定尺寸的小截图。

**位图像完成的马赛克，矢量图像可重新执行的画图说明书。** 这是教学类比，SVG 实际还能包含位图、滤镜和其他复杂内容。[参考：MDN SVG 入门](https://developer.mozilla.org/en-US/docs/Web/SVG/Tutorials/SVG_from_scratch/Introduction)

## 二、为什么放大通常仍然清晰

SVG 的几何形状不依赖固定的像素网格。显示时，浏览器或绘图软件会根据目标大小，把形状绘制到当前设备的像素上。

所以不是“屏幕上没有像素”，而是**每次按目标尺寸生成画面，不受原先那张小位图分辨率的直接限制**。

“无限放大都清晰”是便于记忆的简化说法，需要注意：

- SVG 中嵌入的照片仍然是位图，放大后不会自动增加细节。
- 模糊滤镜本来就可能让边缘模糊；字体和渲染方式也会影响显示效果。
- 截图或导出成固定尺寸的位图后，导出的图片就失去了继续按矢量形状缩放的能力。
- 把一张模糊照片改名成 `.svg`，不会让它变清晰；把照片嵌进 SVG 也不会自动矢量化。

## 三、它和 PNG、JPG 有什么区别

- **PNG**：Portable Network Graphics（便携式网络图形），读作 P-N-G，常用于需要无损保存或透明背景的图片。
- **JPEG**：Joint Photographic Experts Group（联合图像专家组，格式名称来源），常读作“jay-peg”；`.jpg` 与 `.jpeg` 通常是同一种格式的不同扩展名。

| 比较项 | SVG | PNG | 常见 JPEG/JPG |
| --- | --- | --- | --- |
| 主要表示方式 | 形状、路径、文字等描述，也能包含位图 | 像素网格 | 像素网格 |
| 放大 | 矢量部分可重新按尺寸绘制 | 受原图分辨率限制 | 受原图分辨率限制 |
| 常见用途 | 图标、标志、示意图、图表 | 截图、透明图、精确线条与文字图片 | 照片、复杂自然场景 |
| 透明背景 | 支持 | 支持 | 常见格式不支持透明通道 |
| 编辑方式 | 可修改形状参数、路径、颜色和文字 | 主要编辑像素 | 主要编辑像素 |

普通 PNG 的压缩是无损的；常见 JPEG 照片采用有损压缩，即允许丢失一些细节以缩小文件。**无损压缩不等于放大不失真**，因为位图仍只有原来那些像素信息。[参考：MDN 图片格式指南](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Formats/Image_types)

SVG 也不一定更小：一个简单图标可能只需要少量形状，而大量复杂路径、滤镜和嵌入照片可能让 SVG 很大、绘制很慢。不要仅凭扩展名判断质量、体积和速度。

## 四、它为什么能用记事本打开

SVG 通常以 **XML（Extensible Markup Language，可扩展标记语言，读作 X-M-L）**文本描述图形。XML 是用标签组织信息的一种格式。

最小示例，初学者可以先看后面的解释，不必记语法：

```xml
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 100 100" width="200" height="200" role="img" aria-label="蓝色圆形">
  <circle cx="50" cy="50" r="30" fill="blue" />
</svg>
```

- 第一行：建立 SVG 图形区域，设置内部坐标范围和默认显示尺寸，并提供“蓝色圆形”这个可访问名称。
- 第二行：画圆；`cx`、`cy` 是圆心坐标，`r` 是半径，`fill` 是内部填充颜色。
- 第三行：结束这张 SVG 的描述。

`viewBox="0 0 100 100"` 描述内部坐标区域：起点为 `(0, 0)`，宽高各为 100 个坐标单位。它**不是把图像固定成 100×100 像素的位图**。示例默认显示区域是 200×200，内部形状会映射过去。

`xmlns` 中看起来像网址的字符串是命名空间标识，用于说明这些标签属于 SVG；它本身不是要求浏览器把图片上传到该网址。[参考：MDN viewBox](https://developer.mozilla.org/en-US/docs/Web/SVG/Reference/Attribute/viewBox)

你可以手写简单 SVG，也可以用绘图软件导出。复杂标志和插画通常不需要人逐条手写路径。

## 五、SVG 和网页怎么配合

- [[HTML]] 负责页面内容与结构，可以引用 `.svg` 文件，也可以直接包含 `<svg>` 图形。
- [[CSS]] 负责样式；在合适的嵌入方式下，可以改变 SVG 的颜色、尺寸等外观。
- JavaScript 可以操作内联 SVG 的图形元素，实现交互和动画；它不是显示静态 SVG 的必需条件。
- [[渲染逻辑]] 描述浏览器如何把这些图形规则变成最终画面。

这里要区分两种常见方式：

1. **作为图片引用**：类似使用一张照片，把 SVG 当成独立图片展示。
2. **内联在页面中**：把 SVG 标签直接放进网页，页面可以更方便地操作里面的圆、路径、文字等元素。

两种方式的样式控制和安全规则不完全一样，不能假设外层页面总能直接改到独立 SVG 文件里的每一个图形。

## 六、为什么网页图标经常使用它

例如网站上的放大镜、返回箭头、播放按钮，通常由简单形状组成，适合用 SVG 描述：

- 同一个图形可以适配不同显示尺寸；
- 按嵌入方式和实现设计，可以切换深色、浅色主题；
- 可以组合成图表、示意图，必要时增加交互；
- 不需要为每一个尺寸都准备一张独立的小位图。

照片则有复杂纹理和大量细节，通常更适合位图格式。SVG 并不是所有图片的替代品。

## 七、陌生 SVG 能不能当成普通静态图片信任

**不能仅凭“它是图片”就假定没有主动内容。** SVG 可以包含脚本、链接和外部资源引用。

浏览器把 SVG 当作 `<img>` 等图片资源加载时，会对脚本、外部资源等施加限制；直接作为文档打开、内联到页面或以文档方式嵌入时，规则不同。[参考：MDN SVG 作为图片时的限制](https://developer.mozilla.org/en-US/docs/Web/SVG/Guides/SVG_as_an_image)

学习时记住：

- 不把陌生来源的 SVG 文本未经检查直接塞进网页。
- 开发允许用户上传图片的系统时，需要按使用方式检查、清理和隔离不可信内容。
- SVG 是文本不代表无风险；复杂内容也可能消耗大量渲染资源。

## 八、与刚学过的“向量引擎”和 PWA 有什么关系

### SVG 的矢量，不是向量检索中的嵌入向量

中文里 Vector 可以译作“矢量”或“向量”，但这里的用途不同：

- **SVG**：用位置、形状、路径等几何描述来画图。
- **向量检索**：把内容表示为一组特征数字，再寻找相似项，详见 [[向量引擎、向量数据库与相似度检索]]。

不是“用了 SVG 就需要向量数据库”，也不是“保存到向量数据库就能生成 SVG”。

### PWA 是应用体验，SVG 是图形格式

PWA（Progressive Web App，渐进式 Web 应用，读作 P-W-A）网站可以像其他网站一样使用 SVG 图标，但两者不是同一层面的技术。应用安装图标的格式和尺寸还要符合目标平台的要求，不能只准备一个 SVG 就假定到处可用。见 [[React前端技术栈：Vite、Router、Zustand与PWA#十一、PWA：把 Web 应用逐步增强得更像 App|PWA 入门]]。

## 学习建议

1. 先分清“保存像素”和“描述形状”。
2. 再认识圆、矩形、路径、填充和描边。
3. 理解 `viewBox` 的坐标与实际显示尺寸不是同一个概念。
4. 最后再学习动画、交互和复杂滤镜，不必一开始就背路径语法。

记忆口诀：**照片常用像素记录，图标常用形状描述；SVG 可以重新画大，但不会凭空补出照片细节。**
