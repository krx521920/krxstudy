# 操作系统、内核与硬件管理

> [!summary] 一句话解释
> 操作系统管理处理器、内存、存储和设备，为多个程序提供可使用、受保护的运行环境；内核是其中承担关键资源管理与权限工作的核心部分。

**OS = Operating System（操作系统，读 O-S）**。Windows、macOS 和完整的 Linux 发行版是常见操作系统环境；严格说 Linux 这个名字也常特指内核，要结合语境。

像共享办公楼的管理系统：各团队不能随意占用别人的房间，电梯、仓库和网络需要协调，工作人员通过规定接口申请资源。

## 操作系统管理什么

| 管理内容 | 解决的问题 |
|---|---|
| 进程与线程 | 哪些程序在运行，如何分配处理器时间 |
| 虚拟内存 | 地址如何映射，程序怎样彼此隔离，内存怎样分配 |
| 文件系统 | 文件名、目录、权限怎样对应存储内容 |
| 设备与驱动 | 如何对不同硬盘、网卡、显卡提供可用接口 |
| 网络 | 数据如何经过协议栈收发 |
| 安全与身份 | 谁能访问哪些资源，哪些操作需要更高权限 |
| 服务与运行环境 | 为应用提供常用系统能力 |

不是所有这些工作都必定全部实现于内核。操作系统设计可把一部分服务放到用户空间，具体架构不同。

## 内核和桌面界面不是同一个东西

Kernel（内核）处理关键底层机制；桌面窗口、文件管理器和命令行解释器是与它配合的不同组件。

没有漂亮桌面，不代表没有操作系统。服务器或嵌入式设备可以只有必要服务和命令行，见 [[Linux为什么可以做得很小]]、[[Unix与Linux设计哲学：文件、小工具与管道]]。

也不是所有设备都需要完整桌面系统。**RTOS = Real-Time Operating System（实时操作系统，读 R-T-O-S）** 强调在约定条件下满足时间约束；“实时”不是泛指跑分更高。

## 用户态、内核态与系统调用

User Mode（用户态）通常用于普通应用，权限受限制；Kernel Mode（内核态）可执行更多受保护操作，错误影响也可能更大。

应用需要受保护资源时，通过 System Call（系统调用）等受控入口请求服务。例如打开文件、创建进程、申请某些内存资源。

这不是说 CPU 每执行一次加法都必须先问 OS。应用被调度后，在用户态直接执行允许的指令；系统调用、中断、异常等机制让执行转入相应系统处理流程。

**API = Application Programming Interface（应用程序编程接口，读 A-P-I）** 与系统调用不完全相同。应用调用的高级 API 可能在用户空间完成，也可能最终调用一个或多个系统调用。详见 [[SDK与API]]。

## 驱动与操作系统：通用请求怎样变成设备动作

本篇的设备驱动指软件，参与设备识别、初始化、请求提交、结果处理和错误管理等。电路里也有“驱动芯片”，例如控制功率开关的栅极驱动器，但那是硬件语境，不是操作系统里的设备驱动程序。

某些驱动运行在内核态，某些部分可以在用户态。普通应用通常不应自行读取任意硬件寄存器来控制设备；系统通过权限、驱动与设备接口协调访问。

详细沿用 [[设备驱动：操作系统控制硬件的翻译层]] 与 [[内存映射、MMIO与代码控制硬件]]，不重新创建同名笔记。

## BIOS、UEFI、固件与 OS 的分工

**BIOS = Basic Input/Output System（基本输入/输出系统，常读“拜奥斯”）**，通常指传统 PC 平台固件体系。

**UEFI = Unified Extensible Firmware Interface（统一可扩展固件接口，读 U-E-F-I）**，定义现代平台固件与操作系统加载器等之间的接口及启动环境。

固件负责建立早期平台条件、寻找并启动适当加载器；加载器将控制交给操作系统内核；内核继续初始化并启动服务和应用。

```mermaid
flowchart LR
    Reset["处理器复位"] --> FW["平台固件：初始化必要硬件"]
    FW --> Loader["操作系统加载器"]
    Loader --> Kernel["内核、驱动与资源管理"]
    Kernel --> Apps["服务和用户应用"]
```

这描述常见有完整 OS 的平台，嵌入式还可能有片内 Boot ROM、多个加载阶段或直接运行裸机固件。操作系统启动后，部分固件/管理控制器仍继续提供功能，不是整个固件世界都“下班了”。

主板固件常保存在 Flash 等非易失性存储中；OS 文件常保存在硬盘，运行时部分代码和数据进入主内存。**软件职责与保存它的介质必须分开。** 详见 [[固件、ROM代码与计算机启动链]]。

## CPU 不装操作系统还能工作吗

能。处理器按照复位规则开始取指，满足必要硬件条件即可执行相应代码；裸机程序可以直接管理设备和工作流程。

OS 的价值不是让 CPU 第一次拥有计算能力，而是为较复杂的多个任务复用调度、内存、设备和保护等机制。这里能联系 [[嵌入式系统为什么经常使用Linux]]：系统复杂度高时，成熟 OS 能节省大量重复开发。

## PCB 的另一个含义：进程控制块

操作系统教材中的 **PCB = Process Control Block（进程控制块，读 P-C-B）** 是管理进程所需信息的软件数据结构概念。

可能关联进程标识、运行状态、调度信息、地址空间、资源以及恢复执行所需上下文等。实际系统可把这些信息分散在多个结构里，不要求真的有一个同名完整对象。

而硬件中的 PCB = Printed Circuit Board（印刷电路板）。一个是内存中的管理信息，一个是实体电路板，必须按上下文区分。进程、线程与上下文切换见 [[进程、线程、多进程与多线程]]。

## “同一硬件能装不同 OS”有什么条件

处理器架构、启动支持、驱动和应用生态需要匹配。同为 64 位不代表 x86-64 和 Arm64 系统镜像可以随意互换；能成功启动也不代表全部外设已获得完整支持。

同理，CUDA 或其他计算应用的运行，需要相应系统、驱动、设备与库的组合，见 [[GPU、显存与CUDA并行计算]]。

## 学习建议与误区

先能说清“应用→系统接口→内核/驱动→设备”的关系，再学习虚拟内存和调度。不要把 OS、CPU、驱动、固件都统称成“系统芯片”。
