# Linux 的主要用途、普及原因与桌面现状

> [!summary] 一句话结论
> **Linux 主要被用于服务器、云平台、网络设备、手机和各种嵌入式产品，也被开发者和部分普通用户当作桌面系统；它流行是因为开放、可定制、自动化能力强、适合长期运行并拥有庞大生态，而消费级电脑较少预装 Linux，主要是软件兼容、厂商售后、用户习惯和市场网络效应造成的，并不是 Linux 不能安装在普通电脑上。**

最先记住三句话：

1. **Linux 不只是一种“电脑桌面”，它更像可以组成许多不同操作系统的通用内核。**
2. **你看不见 Linux，不代表身边没有 Linux。网站服务器、路由器、Android 手机和许多智能设备可能都在使用它。**
3. **电脑不需要为 Linux 单独发明一种硬件；同一台普通 x86-64 电脑通常可以安装 Windows，也可以安装 Linux。**

## 一、这里说的 Linux 到底是什么

日常所说的“Linux”可能有两种含义。

### 1. Linux 内核

**Kernel（内核，读作“科讷尔”）**负责：

- 管理 CPU、内存和进程；
- 操作磁盘、网卡、USB、显卡等硬件；
- 提供文件系统；
- 实现 TCP/IP 等网络能力；
- 处理用户和权限；
- 让应用通过系统调用使用这些能力。

### 2. Linux 发行版

**Distribution（发行版，常简称 Distro）**是在 Linux 内核之外，配上用户空间软件形成的完整系统。

```text
Linux 内核
+ GNU/BusyBox 等系统工具
+ 软件库
+ Shell
+ 软件包管理器
+ 后台服务
+ 可选的图形桌面与应用
= Linux 发行版
```

常见发行版包括：

- Ubuntu；
- Debian；
- Fedora；
- Arch Linux；
- Linux Mint；
- openSUSE；
- Alpine Linux；
- 面向路由器的 OpenWrt。

因此，“Linux 能做什么”不是由内核一个组件决定的，还取决于围绕内核组装了什么软件。

Linux 官方也提醒初学者：内核只是完整系统的一个组件，普通用户通常应该获取某个发行版，而不是单独下载内核源码。

详见 [[Linux为什么可以做得很小]]。

## 二、Linux 主要用来做什么

Linux 的用途可以按场景分成七大类。

```mermaid
flowchart TD
    Linux[Linux 内核与发行版]
    Linux --> Server[服务器与数据中心]
    Linux --> Cloud[云计算与容器平台]
    Linux --> Network[路由器、NAS 与网络设备]
    Linux --> Mobile[Android 手机与移动设备]
    Linux --> Embedded[智能电视、汽车、相机和工业设备]
    Linux --> Dev[编程、DevOps 与安全研究]
    Linux --> Desktop[个人桌面与游戏设备]
```

### 1. 网站和应用服务器

这是 Linux 最重要的用途之一。

你访问一个网站时，背后可能有许多 Linux 服务器分别负责：

- 接收 HTTP/HTTPS 请求；
- 运行 Java、Go、Python、Node.js 等后端程序；
- 运行 Nginx、Apache 等 Web 服务器；
- 运行 MySQL、PostgreSQL 等数据库；
- 保存文件和对象；
- 处理登录、支付和消息；
- 收集日志和监控指标。

服务器通常不需要显示器和漂亮桌面，只需稳定地在后台提供网络服务。Linux 很适合通过命令行、配置文件和自动化脚本进行远程管理。

### 2. 云计算和容器平台

云服务器不一定对应一台固定的物理电脑。云平台会把大量物理机器组织成可自动创建、扩容和销毁的计算资源。

Linux 在这里常被用作：

- 云虚拟机的操作系统；
- Docker 等容器的宿主系统；
- Kubernetes 集群节点；
- CI/CD 构建和部署机器；
- 网关、代理、负载均衡和监控系统。

Linux 内核提供的 namespace、cgroup、网络和文件系统机制，是 Linux 容器隔离和资源控制的重要基础。

### 3. 路由器、交换机、NAS 和网络设备

家里的路由器、企业网关、无线接入设备、网络存储设备可能使用裁剪后的 Linux。

它们利用 Linux 的：

- TCP/IP 网络协议栈；
- 路由、桥接和转发；
- 防火墙与网络地址转换；
- 网卡、Wi-Fi、USB 和存储驱动；
- 多用户与权限机制；
- 远程管理和日志能力。

OpenWrt 就是面向路由器和嵌入式网络设备的 Linux 发行版。

### 4. Android 手机和平板

Android 不是普通的 Ubuntu 桌面，也不使用完全相同的应用生态，但 Android 的内核以 Linux 长期支持内核为基础，再加入 Android 所需的修改。

所以可以说：

```text
Android 使用 Linux 内核
但 Android 不等于传统 GNU/Linux 桌面发行版
```

你每天使用 Android 手机时，实际上已经在间接使用 Linux 内核。

### 5. 嵌入式和智能设备

**Embedded System（嵌入式系统）**是嵌入某种产品内部、负责固定功能的计算系统。

例如：

- 智能电视和机顶盒；
- 网络摄像头；
- 车载娱乐和信息系统；
- 工业控制器与机器人；
- 无人机；
- 智能音箱；
- 售货机和广告屏；
- 开发板，例如 Raspberry Pi；
- 医疗、科研和测量设备。

Linux 可以按固定硬件裁剪，只保留需要的驱动和程序，所以很适合资源受限但又需要网络、文件系统、多进程和复杂应用的设备。Linux、RTOS 与裸机的选型边界，以及 BSP、设备树和构建系统的具体作用，详见 [[嵌入式系统为什么经常使用Linux]]。

### 6. 编程、DevOps 和技术研究

Linux 对开发者很有吸引力，因为它提供：

- Bash 等 Shell；
- Git、SSH、编译器和调试器；
- Python、Go、Java、Rust、C/C++ 等开发环境；
- 包管理器；
- 容器和虚拟化工具；
- 与生产服务器相近的环境；
- 大量可以脚本化和自动化的命令行工具。

**DevOps（Development and Operations，开发与运维协作）**强调自动构建、测试、部署和监控。Linux 的命令行和自动化生态与这类工作非常契合。

网络安全、操作系统、编译器、云原生和 AI 工程领域也经常使用 Linux。

### 7. 个人电脑、工作站和游戏设备

Linux 也可以用于普通桌面：

- 浏览网页；
- 看视频和听音乐；
- 编辑文档；
- 编程；
- 图形设计和音视频制作；
- 科研计算；
- 玩一部分原生或通过兼容层运行的游戏。

Linux 可以安装 GNOME、KDE Plasma、Cinnamon 等桌面环境，使用鼠标、窗口、任务栏和设置界面，并不是只能面对黑色命令行。

Steam Deck 就是一个很直观的例子：它运行基于 Arch Linux 的 SteamOS 3，并提供 KDE Plasma 桌面。

## 三、为什么这么多人和公司使用 Linux

### 原因 1：源代码开放，可以检查和修改

Linux 内核采用开源方式开发。企业、研究机构和个人可以：

- 查看代码；
- 修复问题；
- 为新硬件添加驱动；
- 按产品需求裁剪；
- 把修改提交给上游社区；
- 在许可证允许范围内发布自己的系统。

这减少了对单一操作系统厂商产品路线的依赖。

但要注意：

> **Open Source（开源）不等于完全没有成本。**

软件许可证可能不收费，但研发、测试、硬件适配、安全维护、技术支持和员工培训仍然需要成本。

### 原因 2：可定制范围非常大

同一个 Linux 内核可以被组装成：

- 数百 MB 或更小的嵌入式镜像；
- 没有图形界面的服务器；
- 完整桌面系统；
- Android 手机系统的一部分；
- 路由器固件；
- 游戏掌机系统。

企业可以只保留需要的功能，也可以修改启动流程、桌面、更新机制和安全策略。

### 原因 3：适合服务器长期、自动化运行

服务器看重的通常不是“界面是否漂亮”，而是：

- 能否长期稳定运行；
- 能否远程管理；
- 能否批量部署；
- 能否用脚本重复配置；
- 是否方便查看日志和限制权限；
- 是否容易与网络、存储和监控系统结合；
- 出问题后是否容易追踪。

Linux 的进程、权限、网络、日志、Shell 和软件包生态为这些工作提供了成熟基础。

“Linux 稳定”也不表示永远不会崩溃，而是它适合经过测试、限制变更并持续维护的服务环境。

### 原因 4：网络和多用户能力成熟

Linux 源于 Unix 类系统的多用户、进程隔离、权限和网络设计，适合让许多服务同时运行，并限制不同进程和用户能够访问的资源。

这与服务器、云计算和网络设备的需求高度匹配。

### 原因 5：能运行在很多 CPU 架构和硬件上

Linux 最初面向 32 位 x86 PC，但现在支持多种 32 位和 64 位处理器架构。

这意味着厂商可以把相似的软件生态带到：

- x86-64 服务器和个人电脑；
- ARM 手机、开发板和服务器；
- RISC-V 等新架构；
- 各种面向产品的 SoC。

**SoC（System on Chip，片上系统）**是把 CPU、内存控制器、图形、外设接口等组件集成在一块芯片中的设计。

### 原因 6：软件生态和社区规模大

大量基础设施软件会优先支持 Linux，例如：

- Web 服务器；
- 数据库；
- 编程语言工具链；
- 容器与集群系统；
- 自动化运维工具；
- AI 和科学计算环境。

当开发者、云平台和软件厂商都支持同一个平台时，会形成 **Network Effect（网络效应）**：使用者越多，工具越多；工具越多，又吸引更多使用者。

### 原因 7：发行和部署方式灵活

厂商可以：

- 自己构建镜像；
- 使用社区发行版；
- 购买 Red Hat、Canonical、SUSE 等公司的企业支持；
- 在云平台直接创建 Linux 虚拟机；
- 用容器交付应用；
- 在自己的设备中预装定制系统。

所以“开源社区版本”和“付费企业支持”可以同时存在。

### 原因 8：透明不等于自动安全，但便于建立安全工程

开放代码让社区和企业能够检查实现、发布修复和审计组件；Linux 也提供权限、namespace、capabilities、安全模块和防火墙等机制。

但 Linux 并不会自动安全。旧内核、错误权限、弱密码、开放端口和不更新的软件同样危险。

## 四、为什么普通商店里的电脑很少预装 Linux

首先修正说法：

> **不是“没有 Linux 电脑”，而是“面向大众销售、默认预装传统桌面 Linux 的电脑远少于 Windows 和 macOS 电脑”。**

造成这个现象的不是一个技术原因，而是多种商业和生态因素叠加。

### 原因 1：操作系统不要求专用 CPU

一台常见 x86-64 笔记本的硬件并不天然属于 Windows。

同一台电脑可能：

- 只安装 Windows；
- 只安装 Ubuntu；
- 同时安装 Windows 和 Linux；
- 主系统使用 Windows，在虚拟机中运行 Linux；
- 使用 WSL 在 Windows 中获得 Linux 环境。

因此厂商没有必要设计一类完全不同的“Linux 专用电脑”。真正关键的是驱动、固件和整机功能是否经过测试。

### 原因 2：普通用户先看应用，不先看内核

大多数消费者买电脑是为了：

- 使用 Office；
- 上网和视频会议；
- 使用学校或公司的指定软件；
- 运行 Adobe、工程、财务和行业软件；
- 玩指定游戏；
- 使用打印机、扫描仪等外设。

如果这些应用明确要求 Windows 或 macOS，用户就会购买相应系统。即使 Linux 本身能完成大量工作，不能运行某个关键应用也可能直接影响购买决定。

### 原因 3：Windows 已形成桌面市场的网络效应

长期以来：

```text
Windows 用户多
→ 软件厂商优先开发 Windows 版
→ 硬件厂商优先测试 Windows 驱动
→ 学校和公司优先教授、部署 Windows
→ 售后人员更熟悉 Windows
→ 消费者更倾向继续购买 Windows
→ Windows 用户继续增多
```

这是一种循环，不表示 Windows 在所有技术指标上都绝对优于 Linux，而是已有生态会强化自身。

### 原因 4：硬件“能启动”不等于整机体验完整

Linux 对常见 CPU、磁盘、网卡、USB 等硬件支持很好，但具体笔记本还可能涉及：

- 指纹识别器；
- 摄像头特殊功能；
- 触摸屏和手写笔；
- 独立显卡切换；
- Wi-Fi 与蓝牙芯片；
- 睡眠、休眠和唤醒；
- 风扇与功耗管理；
- 厂商快捷键；
- 雷电接口和扩展坞；
- 专有打印机和扫描仪驱动。

厂商如果预装 Linux，就需要验证这些功能并承担售后责任，而不能只证明系统出现了桌面。

### 原因 5：Linux 桌面选择很多，厂商支持矩阵更复杂

“预装 Linux”还需要继续选择：

- Ubuntu、Fedora、Debian 还是其他发行版；
- 哪个发行版版本；
- GNOME、KDE Plasma 还是其他桌面；
- 使用 Deb、RPM、Flatpak、Snap 等哪种软件交付方式；
- 支持几年；
- 谁负责升级失败和驱动问题。

选择多对技术用户是自由，对面向数百万普通消费者的厂商则意味着更多测试和客服组合。

### 原因 6：大多数 Linux 爱好者会自行安装

熟悉 Linux 的用户往往会：

- 购买兼容性较好的普通电脑；
- 自己选择发行版；
- 自己分区安装；
- 更换桌面和内核；
- 处理驱动或配置问题。

这会让“预装 Linux”看起来需求更小：最有兴趣的人反而不一定要求厂商预装。

### 原因 7：零售、营销和售后渠道更少

预装系统不仅是把镜像复制进硬盘，还包含：

- 销售页面和包装；
- 首次开机设置；
- 恢复分区；
- 驱动和固件更新；
- 客服培训；
- 退换货判断；
- 与第三方软件和云服务的合作。

Windows PC 已经拥有成熟渠道。Linux 机型通常集中在开发者、工程师、企业采购或特定地区，不一定出现在普通线下商店。

## 五、其实已经存在“Linux 电脑”

### 1. 专门销售 Linux 电脑的厂商

System76 等厂商销售预装 Linux 的笔记本和台式机。此类产品会围绕 Linux 选择硬件并提供相应支持。

### 2. 大厂的 Linux 兼容或预装机型

Canonical 维护 Ubuntu Certified Hardware（Ubuntu 认证硬件）目录，其中包含大量 Dell、HP、Lenovo 等厂商的笔记本。

“通过 Ubuntu 认证”和“你所在地区一定能买到预装 Ubuntu 的版本”不是一回事：

- 认证说明特定配置经过兼容性测试；
- 实际是否预装销售取决于机型、地区、渠道和时间；
- 同一型号不同网卡、显卡和指纹模块，也可能产生不同结果。

### 3. Steam Deck

Steam Deck 运行 SteamOS 3，官方技术规格说明它基于 Arch，并使用 KDE Plasma 桌面。它是一台围绕特定 Linux 系统优化的消费设备，只是产品通常被叫作“掌机”，而不是“Linux 笔记本”。

### 4. Chromebook

Chromium OS 使用 Linux 内核，ChromeOS/Chromebook 也属于“Linux 内核进入消费电脑”的重要形式。

但 ChromeOS 的界面、应用模式、系统管理方式与 Ubuntu 等传统 GNU/Linux 桌面不同，所以普通用户不会把它称为 Linux 笔记本。

### 5. Android 设备和其他隐藏设备

Android 手机、电视盒子、路由器和 NAS 等产品也可能使用 Linux 内核。厂商通常宣传的是 Android、电视系统、路由功能或产品品牌，而不是底层 Linux。

因此更准确的观察是：

> **Linux 在“看不见操作系统的设备”中非常普遍，在“用户主动选择桌面操作系统的传统 PC”中相对少见。**

## 六、为什么 Linux 在服务器成功，在大众桌面相对弱

两种场景的购买标准不同。

| 维度 | 服务器和云平台 | 普通个人电脑 |
|---|---|---|
| 主要使用者 | 运维、开发和平台工程师 | 普通消费者、学生和办公人员 |
| 主要目标 | 稳定提供网络服务、自动化、批量管理 | 使用熟悉的图形应用、游戏和外设 |
| 是否需要桌面 | 通常不需要 | 通常需要 |
| 软件选择重点 | Web、数据库、容器、监控和编程工具 | Office、Adobe、行业软件、游戏和外设工具 |
| 管理方式 | SSH、配置文件、脚本、镜像和 API | 鼠标、应用商店、安装程序和售后服务 |
| 更换软件的能力 | 团队可以开发、适配或容器化 | 用户通常必须使用指定商业软件 |
| 系统可定制性 | 很重要 | 多数用户不关心 |
| 学习和维护人员 | 专业技术人员 | 希望开机即用的消费者 |

Linux 的优势正好匹配服务器：自动化、远程管理、开放、可裁剪和基础设施生态。

而大众桌面的决定性因素往往是：某个软件能不能用、文件格式是否兼容、同事是否使用、游戏能不能运行、出问题找谁解决。这些是生态问题，不只是内核性能问题。

## 七、Linux 桌面现在能不能日常使用

能不能使用取决于你的任务，而不是只看“Linux 好不好”。

### 比较适合的情况

- 学习编程、服务器、网络和操作系统；
- Web 开发、后端开发、云原生和 DevOps；
- 主要使用浏览器和跨平台软件；
- 使用 LibreOffice 等工具可以满足文档需求；
- 愿意学习系统和处理少量兼容问题；
- 重视系统控制权和可定制性；
- 已确认常用游戏和硬件可以运行。

### 需要谨慎的情况

- 强依赖完整桌面版 Microsoft Office 的高级功能或宏；
- 强依赖 Adobe Creative Cloud；
- 学校、公司指定只提供 Windows/macOS 版本的软件；
- 使用特殊财务、工程、医疗或设备控制软件；
- 必须运行带不兼容反作弊系统的游戏；
- 笔记本的指纹、独显切换、休眠等功能没有确认兼容；
- 不愿意投入时间学习新的软件和故障处理方式。

这时可以继续把 Windows 作为主系统，同时通过 WSL、虚拟机或远程服务器学习 Linux。

## 八、初学者怎样体验 Linux 最稳妥

### 方案 1：WSL

**WSL（Windows Subsystem for Linux，适用于 Linux 的 Windows 子系统）**适合在 Windows 中学习：

- Linux 命令；
- Bash；
- Git；
- Python、Node.js、Go 等开发；
- Web 后端和容器相关知识。

优点是不用重装系统；缺点是不能完全代表普通 Linux 桌面和裸机硬件管理。

### 方案 2：虚拟机

在 VMware、VirtualBox 或 Hyper-V 中安装 Ubuntu，可以体验完整 Linux 桌面，同时不会改动真实磁盘分区。

这是初学者最容易回退的完整体验方案。

### 方案 3：Live USB

把 Linux 制作成启动 U 盘，先不安装，从 U 盘启动测试：

- Wi-Fi；
- 声音；
- 触摸板；
- 蓝牙；
- 屏幕亮度；
- 摄像头；
- 外接显示器。

Live 环境的性能和持久化行为可能与正式安装不同，但适合做硬件兼容初检。

### 方案 4：双系统

同一台电脑安装 Windows 和 Linux，开机时选择。

优点是 Linux 能直接使用真实硬件；风险包括分区操作、引导配置、磁盘加密和系统更新时间差异。开始前必须备份重要文件和恢复密钥。

### 方案 5：备用电脑或预装 Linux 电脑

如果希望长期学习又不影响主力环境，可以使用旧电脑、备用电脑，或购买经过 Linux 兼容测试并提供支持的机型。

### 给你的建议

作为计算机初学者，建议顺序是：

```text
WSL 学命令和开发
→ 虚拟机体验完整系统
→ Live USB 检查真实硬件
→ 确定常用软件兼容后，再考虑双系统或独立安装
```

## 九、常见误区

### 误区 1：Linux 只有程序员使用

错误。程序员经常直接操作 Linux，但普通人也会通过 Android、ChromeOS、SteamOS、路由器和智能设备间接使用 Linux。

### 误区 2：Linux 只能运行命令行

错误。Linux 有 GNOME、KDE Plasma 等完整桌面环境。服务器经常不安装桌面，是因为不需要，不是因为不能。

### 误区 3：Linux 免费，所以没有公司维护

错误。Linux 同时有社区开发者、硬件厂商、云平台和商业 Linux 公司参与。开源软件也可以提供付费支持和企业服务。

### 误区 4：开源就一定安全

错误。代码可审查只是条件之一，是否及时更新、正确配置和限制权限同样重要。

### 误区 5：没有 Linux 专用 CPU，所以 Linux 兼容性差

错误。Linux 支持多种 CPU 架构。个人电脑体验是否完整，更多取决于具体外设、驱动、固件和厂商测试。

### 误区 6：Ubuntu 认证就代表商店一定预装销售

错误。认证主要说明特定硬件配置通过兼容测试；实际预装产品还受地区、配置、渠道和销售计划影响。

### 误区 7：Android 就是手机里的 Ubuntu

错误。Android 使用 Linux 内核，但用户空间、应用框架、图形系统、权限模型和应用格式都与普通 Ubuntu 桌面不同。

### 误区 8：服务器使用 Linux，所以 Linux 桌面一定更适合所有人

错误。服务器和桌面的任务、软件生态、管理人员与购买标准不同。适合服务器的优势不会自动解决桌面商业软件兼容问题。

## 十、最终记忆

### Linux 主要在哪里

```text
看得见的 Linux：
Ubuntu/Fedora 桌面、开发工作站、Steam Deck

不容易看见的 Linux：
服务器、云平台、Android、Chromebook、路由器、NAS、电视和嵌入式设备
```

### 为什么受欢迎

```text
开放和可修改
+ 支持多种硬件
+ 网络、进程和权限基础成熟
+ 容易远程管理与自动化
+ 软件和社区生态庞大
+ 可以从微型设备扩展到大型服务器
= 特别适合基础设施和定制产品
```

### 为什么普通 PC 预装少

```text
Windows 已有桌面网络效应
+ 大众依赖指定商业软件和游戏
+ 厂商需要承担驱动、测试和售后成本
+ Linux 发行版和桌面选择较多
+ Linux 爱好者常常自行安装
= 大众零售渠道中的预装 Linux 机型相对少
```

最准确的一句话是：

> **Linux 并不是“没人把它装进电脑”，而是它最成功的地方恰好位于服务器和各种专用设备中；在那里，人们购买的是网站、云服务、路由功能或智能产品，而不是一个标着 Linux 的桌面。**
