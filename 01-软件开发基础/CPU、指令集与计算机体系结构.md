# CPU、指令集与计算机体系结构

> [!summary] 一句话解释
> CPU 按指令规则执行计算与控制；指令集是软硬件之间的重要约定，同一指令集可以由结构、速度和成本不同的处理器实现。

**CPU = Central Processing Unit（中央处理器，读 C-P-U）**。它不是整台主机，也不是操作系统，而是执行通用计算和控制工作的硬件。

像几种机器都遵循同一本操作手册：手册规定“这个命令应产生什么结果”，机器内部可以采用不同结构。操作手册类似体系结构约定，具体机器结构类似微架构。

## CPU 内部有什么

| 部件或机制 | 做什么 |
|---|---|
| 控制逻辑与译码 | 识别指令，组织需要的操作 |
| 运算单元 | 进行整数、浮点、逻辑等运算 |
| 寄存器 | 保存当前指令直接使用的少量数据和状态 |
| Cache | 缓存近期或附近可能使用的指令和数据 |
| 内存访问与地址转换相关单元 | 访问数据、配合虚拟内存与权限检查 |
| 分支预测、流水线等 | 提高执行效率，具体实现各不相同 |

**ALU = Arithmetic Logic Unit（算术逻辑单元，读 A-L-U）**，是其中进行算术与逻辑操作的一类单元。不是所有运算都由同一个 ALU 完成。

现代处理器可能有多个核心。核心是能执行指令流的重要计算单元；线程是软件执行活动，二者不能简单画等号。多线程技术和操作系统调度见 [[进程、线程、多进程与多线程]]。

## 取指、译码、执行是什么

入门模型：从指令地址取出机器指令 → 译码 → 取得操作数 → 运算/访存 → 更新结果与下一步位置。

**PC = Program Counter（程序计数器，读 P-C）** 是保存指令位置的概念，实际架构可能采用别的寄存器名称，例如 x86 的指令指针。它不是 Personal Computer（个人计算机）那个 PC，也不是 PCB。

现代 CPU 会重叠处理多条指令，甚至进行推测和乱序执行，但对软件呈现的结果必须遵守体系结构规定的行为。因此“取指→译码→执行”是理解模型，不是所有时刻只能处理一条指令。

## 时钟频率为什么不等于性能

GHz 是 Gigahertz（吉赫兹，读 G-H-z），表示每秒十亿个时钟周期的量级。一个周期不是一条完整指令，也不是一种固定工作量。

实际速度还受每周期可完成的有效工作、核心数、缓存命中、内存带宽、程序可并行程度、供电和温度影响。不能只凭“4 GHz 大于 3 GHz”断言不同处理器在所有任务上更快。

加核心也不保证成倍提速：如果步骤严格依赖前一步，很多核心可能等不到可并行工作。复杂度与实际耗时关系见 [[算法复杂度与ASL：渐近符号、平均情况和查找长度]]。

## ISA：处理器与软件约定哪些指令

**ISA = Instruction Set Architecture（指令集体系结构，读 I-S-A）**。它不仅是指令名称列表，还涉及程序可见的寄存器、数据类型、寻址方式、异常和部分内存行为等约定。

同样是“相加”，不同架构可以使用不同机器编码和寄存器名称。CPU 不会因为两段源代码表达相同意思，就天然理解另一架构的机器码。

| 层次 | 重点 | 举例 |
|---|---|---|
| 体系结构 | 对软件可见的行为约定 | 指令集、寄存器、地址与异常规则 |
| 组成/微架构 | 怎样组织部件实现约定 | 流水线、执行单元、缓存组织 |
| 物理实现 | 怎样把设计做成可工作的芯片与系统 | 电路、工艺、布局布线、封装与板级连接 |

教材的“计算机组成”范围可能还包括存储与输入输出系统；微架构更多聚焦处理器内部。它们密切相关，但不需要把所有术语强行当完全同义词。

## Arm 与 x86 是什么

**Arm/ARM** 指处理器架构家族及相关公司品牌；历史 ARM 名称来自 Acorn RISC Machine，后来与 Advanced RISC Machines 的公司名称关联。今天不要把它误认成 RAM 的另一种拼法。

**x86** 源于 Intel 8086 及后续兼容处理器的命名传统，不是某个需要逐字展开的英文缩写。

| 名称 | 常见理解 | 注意 |
|---|---|---|
| x86 | 一族长期演化的指令集；安装包中有时特指 32 位版本 | 看具体语境 |
| x86-64 / x64 / AMD64 | x86 的 64 位扩展家族的常见名称 | AMD64 软件并不因此只能在 AMD CPU 运行 |
| AArch64 / ARM64 | Arm 架构中的 64 位执行/软件目标的常见名称 | 不代表与 x86-64 机器码兼容 |

Arm 不只用于手机，也用于嵌入式设备、电脑与服务器；x86 也不只用于个人电脑。具体产品适用场景取决于设计与生态，不是名称决定用途。

**RISC = Reduced Instruction Set Computer（精简指令集计算机，读 risk）**；**CISC = Complex Instruction Set Computer（复杂指令集计算机，读 sisk）**，是常用的指令集设计风格概念。

不能从“精简/复杂”四个字直接推出谁永远更快、更省电。现代实现很复杂，工艺、微架构、频率策略和负载都影响结果。[Arm 体系结构与微架构说明](https://www.arm.com/architecture/cpu)

## 为什么同为 64 位，程序也不能随便互换

64 位只是某些架构宽度的概括，不代表两台机器使用同一组指令。二进制程序能否运行还需要：

1. 指令集及所需扩展受支持。
2. 操作系统提供相应加载、系统调用与运行环境。
3. **ABI = Application Binary Interface（应用程序二进制接口，读 A-B-I）** 一致，包括调用约定、寄存器使用与数据布局等。
4. 程序依赖的库、设备和权限可用。

因此，同一 x86-64 CPU 上也不能把 Windows 程序和 Linux 程序简单等同。跨平台可以重编译、移植，或在适当条件下使用仿真/二进制翻译；虚拟机也不自动消除所有架构差异。

源代码可移植性与编译后二进制兼容性是两回事，关联 [[常见编程语言及其用途]]、[[Web端、桌面软件与CLI程序的区别]]。

## IBM 系列机：为什么体系结构很重要

**IBM = International Business Machines（国际商业机器公司，读 I-B-M）**。在计算机组成/体系结构课程中，“IBM 系列机”常以 System/360、System/370 为经典案例，不是指全部 IBM 产品都用同一种 CPU。

IBM 于 1964 年推出 System/360，重要思想是：让多个不同价位与性能的型号围绕共同体系结构形成兼容家族。用户升级机器时，已有软件投资尽量延续，而不必每次全部重写。

类比同一套电器插头规范：有小功率和大功率设备，但大家遵守共同接口。规范兼容不代表内部元件、吞吐量和价格相同。

System/370 延续并发展了这种兼容思路。这里最该记住的不是型号年份，而是：

> **同一体系结构，可以有不同组成和物理实现；改变实现可以提升性能，而不必改变软件看到的全部约定。**

实际兼容仍受指令子集、操作系统、外设和特定型号能力等约束，不是无条件让任何旧系统原封不动运行。谈兼容方向时用“新机器支持旧程序”等明确描述，比脱离语境只说向上/向下更清楚。[IBM System/360](https://www.ibm.com/history/system-360)、[IBM System/370](https://www.ibm.com/history/system-370)

IBM 大型机体系与 IBM PC 及其兼容机的历史不是同一条线。看到 IBM 不应直接等同于 x86，也不应把所有 IBM 系列归入 Arm。

## CPU 与主板、GPU、OS 怎样配合

CPU 需要主板供电与散热，访问主内存和外设；操作系统利用其权限与调度机制运行进程；GPU 在合适计算任务中提供大量并行处理，仍需要系统软件配合。

**SoC = System on Chip（片上系统，读 S-O-C）** 可以在一套芯片设计中集成 CPU、GPU、内存控制器等多个功能。因此“CPU 和 GPU 职责不同”不意味着它们永远是两张独立板卡。

## 常见误区与学习建议

- CPU 核心数等于程序线程数：不对，需要操作系统调度，硬件线程也不是完整复制一套核心。
- 频率高就一定快：不对，要看工作量与瓶颈。
- Arm 一定低功耗，x86 一定高功耗：不能脱离具体实现判断。
- 同架构意味着同速度：不对，共同指令约定可以有不同实现。
- IBM 系列机就是所有电脑的型号分类：不对，它是特定厂商和历史架构案例。

学习顺序：寄存器与基本指令 → 取指/译码/执行 → 指令集与微架构区别 → 二进制兼容 → 用 IBM 系列机复述共同架构的价值。
