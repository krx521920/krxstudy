# 算法复杂度与 ASL：渐近符号、平均情况和查找长度

> [!summary] 一句话解释
> 最好、平均、最坏情况下的时间复杂度都可以用大 O 等渐近符号描述；小 o 不是“平均情况”的专用符号。ASL 是平均查找长度，描述按给定概率模型平均需要多少次关键字比较。

## 先回答：都是 o 吗

如果你说的是课本里的 `O(n)`、`O(log n)`，通常是**大写字母 O**，不是数字 0，也不是小写 o。读作“大 O n”“大 O log n”；log 表示对数。

时间复杂度是总的分析概念，平均时间复杂度是其中一种分析角度，所以并不存在“普通时间复杂度一个字母、平均时间复杂度另一个字母”的固定分工。

这三个问题应分开：

| 在问什么 | 相应概念 | 例子 |
|---|---|---|
| 分析哪个情况 | 最好、平均、最坏 | 平均查找用多久 |
| 怎样描述增长边界 | O、Ω、Θ、o 等 | 平均耗时属于 Θ(n) |
| 具体数什么 | 操作次数、比较次数、访问页面数等 | 平均比较 (n+1)/2 次 |

**不是“O=最坏、Ω=最好、Θ=平均”。** 这把两个独立维度混在了一起。

## 生活类比：找一本书

有 n 本没有目录的书，你从第一本开始找：第一本就是目标时很快；最后一本才是目标时要看 n 本；如果每本被找的机会相等，可以计算平均看几本。

“今天平均看了 3 本”和“书架扩大后，平均工作量怎样增长”不是同一问题。前者是具体平均值，后者是复杂度关心的增长趋势。

这里 n 是问题规模，比如书的数量、数组元素个数或表中记录数，具体含义需要先说明。

## T(n)、O(n)、Θ(n) 分别表示什么

设某个选定情况的操作次数为：

$$
T(n)=3n+2
$$

T 是 Time（时间）的常用记号。这里是一个操作计数模型，不是声称程序必定运行 3n+2 秒。

| 符号 | 名称与读法 | 含义（n 足够大时） | 本例 |
|---|---|---|---|
| O(f(n)) | Big-O，大 O | 渐近上界：不超过 f(n) 的某个固定正常数倍 | T(n) 属于 O(n)，也属于较松的 O(n²) |
| Ω(f(n)) | Big-Omega，大 Omega，读“欧米伽” | 渐近下界：至少达到 f(n) 的某个固定正常数倍 | T(n) 属于 Ω(n) |
| Θ(f(n)) | Big-Theta，大 Theta，读“西塔” | 渐近紧确界：上、下界都能用 f(n) 的正常数倍夹住 | T(n) 属于 Θ(n) |
| o(f(n)) | Little-o，小 o | 严格更低增长阶：T(n)/f(n) 趋于 0 | T(n) 属于 o(n²)，不属于 o(n) |

Θ(n) 表示“线性这个增长阶刻画得准确”，不是精确到常数和每一项，也不是“平均”的代号。

O(n²) 对 3n+2 也成立，只是不如 O(n) 紧。题目问时间复杂度时，通常希望尽量给出紧的量级，而不是任意一个很宽的上界。

教材经常写 `T(n)=O(n)`；更严格可写 `T(n)∈O(n)`，把 O(n) 理解为满足条件的一类函数。这不是普通代数中的两边相等，不应反过来随意交换。

### 可选：用定义看懂大 O 与小 o

对这里讨论的最终非负函数，大 O 要求存在固定的 c>0 和起点 n₀，使所有 n≥n₀ 都满足：

$$
0\le T(n)\le c f(n)
$$

小 o 更强：任意小的正常数 c 都能找到相应起点，之后始终压在 c f(n) 以下。f(n) 最终为正时，可以用下面这个极限理解：

$$
\lim_{n\to\infty}\frac{T(n)}{f(n)}=0
$$

例如 n/n²=1/n 越来越接近 0，所以 n=o(n²)；但 n/n=1，所以 n 不是 o(n)。不需要先掌握极限证明，先记住“大小写有严格区别”。

## 最好、平均、最坏：在选择哪一个时间函数

同样规模的不同输入，运行次数可能不同。若 x 表示一个输入：

$$
T_{\mathrm{best}}(n)=\min_{|x|=n}T(x),\qquad
T_{\mathrm{worst}}(n)=\max_{|x|=n}T(x)
$$

平均情况要先给输入分配概率：

$$
T_{\mathrm{avg}}(n)=\mathbb E[T(X)]
=\sum_{|x|=n}P(X=x)T(x)
$$

avg 是 Average（平均）的简写；E 表示 Expectation（期望），即按概率加权的平均。竖线 |x|=n 表示输入规模是 n。

先确定要研究的是哪个函数，再对它求 O、Ω 或 Θ。例如普通顺序查找，在目标一定存在、n 个位置等概率的条件下：

| 情况 | 关键字比较次数 | 相应时间复杂度（每步常数成本） |
|---|---:|---|
| 最好：第一个就是目标 | 1 | Θ(1)，当然也可写 O(1) |
| 最坏：最后一个才是目标 | n | Θ(n)，也可写 O(n) |
| 平均：各位置等概率 | (n+1)/2 | Θ(n)，也可写 O(n) |

很多资料不特别说明时默认讨论最坏情况，这是上下文约定，不是大 O 本身的定义。

## ASL 是什么

**ASL = Average Search Length（平均查找长度，读作 A-S-L）**。

“长度”不是数组长度、字符串长度，也不是内存大小，而是查找过程中关键字比较次数的平均值；某些哈希查找题会具体数探测次数，需要按题目口径理解。

查找成功时，设有 n 个可能目标：

$$
ASL_{\mathrm{成功}}=\sum_{i=1}^{n}p_i C_i
$$

- pᵢ：在查找成功的条件下，目标是第 i 个元素的概率。
- Cᵢ：查找这个元素需要的关键字比较次数。
- 所有 pᵢ 的和为 1。

如果每个目标等概率，才可以简化成普通算术平均：

$$
ASL_{\mathrm{成功}}=\frac{C_1+C_2+\cdots+C_n}{n}
$$

这里的成功条件很重要：没有说明失败请求怎么出现，就不能把成功平均值当作所有请求的总体平均。

## 完整例子：顺序查找五个元素

表中有 `10、20、30、40、50`。规定从左到右逐个判断是否相等，不利用大小顺序提前结束，每个元素被找的概率都是 1/5，且本节只算成功查找：

| 目标 | 比较过程 | 比较次数 |
|---|---|---:|
| 10 | 10 | 1 |
| 20 | 10、20 | 2 |
| 30 | 10、20、30 | 3 |
| 40 | 10、20、30、40 | 4 |
| 50 | 10、20、30、40、50 | 5 |

$$
ASL_{\mathrm{成功}}=\frac{1+2+3+4+5}{5}=3
$$

推广到 n 个元素：

$$
ASL_{\mathrm{成功}}(n)=\frac{1+2+\cdots+n}{n}
=\frac{n(n+1)}{2n}=\frac{n+1}{2}
$$

平均比较 (n+1)/2 次，对应的平均时间复杂度是 Θ(n)，用大 O 表示就是 O(n)。复杂度省略了固定常数因子 1/2 和低阶常数项，但 ASL 计算保留它们。

**n=5 时得到 3，不意味着算法的平均复杂度是 O(1)。** 此时只算了一个规模的具体值；复杂度要考察 n 持续增长。

## 查找失败，以及 n 和 n+1 为什么都有资料写

对以上不带哨兵、仅逐项比较是否相等的实现，找不到目标时需要与 n 个真实元素比较：

$$
ASL_{\mathrm{失败}}=n
$$

如果实现采用哨兵，且把与哨兵的最后一次关键字比较也计入，可能写成 n+1。把循环边界判断也计入，总操作数又不同。先看代码和计数对象，不要把不同定义下的答案当成谁一定写错。

若还知道成功概率为 q，成功时各位置等概率，以上无哨兵实现的总体比较期望为：

$$
\mathbb E[C]=q\frac{n+1}{2}+(1-q)n
$$

这是用成功、失败两种条件平均来加权，不是拿两个数直接除以 2，除非它们确实各有一半概率。

## 不等概率时，平均值不是最好和最坏的中点

对三个元素，成功比较次数分别为 1、2、3。如果查找概率分别为 0.8、0.1、0.1：

$$
ASL_{\mathrm{成功}}=0.8\times1+0.1\times2+0.1\times3=1.3
$$

而“最好＋最坏再除以 2”得到 2，不是正确期望。顺序查找等概率时恰好得到 (1+n)/2，是因为比较次数形成 1～n 的等差序列，不是平均情况的通用公式。

“平均”必须有概率模型。平均复杂度理论也不是在自己的电脑上随便运行几次取平均耗时；后者是实验测量，需要说明样本与环境。

## 二分查找的 ASL 也不直接等于 log₂n

Binary Search（二分/折半查找）在有序数组上每轮缩小候选范围。按一次中间关键字比较/探测为一轮，查找成功的次数由目标在查找判定树中的层数决定。

例如有序数组 1～7，每次选区间中点，查找 1～7 分别访问中间元素的轮数为：

`3、2、3、1、3、2、3`。

等概率成功 ASL 为 17/7≈2.43，既不是最坏的 3，也不是把 log₂7≈2.81 当作精确答案。在这种标准数组实现及等概率模型下，成功平均和最坏时间量级都是 Θ(log n)。

若代码把等于判断和大小判断分开算成两次基本比较，精确计数需要重新计算，但通常不改变这里的对数量级。精确 ASL 必须跟题目规定的比较方式一致。

## 一个可运行的 Python 例子

```python
def linear_search_count(values, target):
    comparisons = 0
    for value in values:
        comparisons += 1
        if value == target:
            return comparisons
    return comparisons

values = [10, 20, 30, 40, 50]
counts = [linear_search_count(values, target) for target in values]
print(counts)                         # [1, 2, 3, 4, 5]
print(sum(counts) / len(counts))       # 3.0：等概率成功 ASL
print(linear_search_count(values, 99)) # 5：失败比较次数
```

函数只统计关键字相等比较次数，不表示返回比较次数就能判断查找是否成功；真正业务函数还需返回位置或成功标记。for 循环的迭代控制、计数加一等没有计入 ASL，但属于实际运行工作。

本篇代码与顺序查找公式已用多个规模核对；二分查找的 7 个成功目标也逐个计数核对。有限样例用于检查代码和算术，不能代替所有规模上的复杂度证明。

## 平均复杂度与均摊复杂度也不同

Amortized Analysis（均摊/摊还分析）分析一串操作的总成本，再分摊到每次操作，不等于给输入分配概率后的平均情况分析。

例如按固定倍数扩容的动态数组，某次追加可能搬移很多元素，但长期一串追加操作的总成本可以是线性的，从而每次追加均摊为 O(1)。这并不承诺任意一次追加都只花常数时间，也不要求“出现什么输入的概率”假设。

## 与数据库索引有什么关系

学习 [[B+树与数据库索引原理]] 时，要区分树的层数、页内比较次数、访问页面数、返回记录数与真实耗时。一次页访问和一次整数比较的成本并不相同。

ASL 反映选定比较模型下的平均工作量；时间复杂度反映随规模增长的量级；实际数据库性能还受缓存、磁盘、锁等待和网络影响，见 [[SQL索引、执行计划与性能优化]]。不能仅靠一个 O(log n) 就推断某条查询必定快多少毫秒。

## 常见误区与学习顺序

- 小 o 是平均情况的符号：错，小 o 表示严格更低的渐近增长阶。
- Θ 表示平均、O 表示最坏：错，分析情况与增长边界是两条轴。
- ASL 就是平均时间复杂度：不完全对，它先是特定基本操作的平均计数；在合适成本模型下可用来推导平均时间量级。
- O(1) 就是执行一次：错，它表示不随选定规模增长的常数量级。
- 同为 O(n) 就一样快：错，常数、实现和运行环境仍不同，而且大 O 本身也可能是较松的上界。
- 忽略常数所以写 O(n/2) 与 O(n) 是两种复杂度：错，两者是同一个增长类。

学习顺序：确定 n → 明确数什么操作 → 列出不同输入的次数 → 指定概率模型 → 算平均次数 → 最后化为 O/Θ 等量级。

自测：若有 9 个等概率成功目标，顺序查找 ASL 是多少？答案是 5；对应平均时间复杂度仍是 Θ(n)，不是把本次的固定 5 当成复杂度。
