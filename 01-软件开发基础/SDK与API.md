# SDK 与 API

## 一句话解释

- **API（Application Programming Interface，应用程序编程接口，按字母读“诶—皮—艾”）**：供其他软件或代码调用的“办事窗口和规则”，不一定对公众开放。
- **SDK（Software Development Kit，软件开发工具包，按字母读“艾斯—迪—凯”）**：为了在某个平台或服务上开发程序而准备的一整套工具箱，其中通常包含 API 的封装。

## 先用生活类比理解

把一家餐厅想成一个软件服务：

- **API 像点餐规则和服务窗口**：菜单上写着能点什么、需要提供什么信息、最后会得到什么。
- **SDK 像餐厅发给合作方的开店工具箱**：不仅有菜单，还可能有现成设备、操作手册、示例、调试工具和培训资料。

因此，API 重点是“**怎样和我交流**”，SDK 重点是“**我给你哪些东西，帮助你开发**”。

## API 到底是什么

API 是一份由程序执行的约定。它通常规定：

1. 可以请求哪些功能。
2. 请求时需要传入什么数据。
3. 数据采用什么格式。
4. 成功会返回什么。
5. 失败时如何表示错误。
6. 是否需要身份认证、是否有限流。

API 不一定经过互联网，常见类型包括：

- **库 API**：例如 Python 字符串的 `upper()` 方法。
- **操作系统 API**：例如程序向 Windows 请求打开文件。
- **浏览器 API**：例如定位、摄像头、剪贴板 API。
- **Web API**：通过 HTTP 请求远程服务器，是日常最常听到的 API。

### 一个 Web API 请求例子

假设天气服务提供：

```text
GET https://weather.example.com/current?city=Shanghai
```

可以把它拆成：

- `GET`：请求方法，表示读取数据。
- `/current`：接口地址的一部分，也叫 endpoint（端点）。
- `city=Shanghai`：参数，告诉服务要查上海。
- 返回值：通常是 JSON，例如 `{"temperature": 30}`。
- 状态码：如 `200` 表示成功，`404` 表示资源没找到，`401` 表示没有通过身份认证。

> [!warning] API Key 不是普通参数
> API Key 常用于证明调用者身份，应像密码一样保护，不能直接写进公开的 GitHub 仓库或前端代码。

## SDK 里通常有什么

不同 SDK 内容不同，但常见组成有：

- 编程语言库或 API 封装；
- 类型定义；
- 文档和教程；
- 示例代码；
- 编译器、调试器或模拟器；
- 测试、打包和部署工具；
- 身份认证、重试、错误处理等通用逻辑。

例如，同样调用天气 API：

```python
# 直接调用 Web API：需要自己拼 URL、发送请求、解析 JSON
response = requests.get(url, params={"city": "Shanghai"})
temperature = response.json()["temperature"]

# 假想的天气 SDK：细节由 SDK 帮忙处理
temperature = weather_sdk.current(city="Shanghai").temperature
```

SDK 并没有创造新的天气数据，它只是让已有 API 更容易、安全、一致地被某种语言调用。

## SDK、API、库和框架的区别

| 概念 | 核心问题 | 典型内容 |
|---|---|---|
| API | 别的软件怎样调用我？ | 方法、参数、数据格式、返回值、错误规则 |
| SDK | 怎样更方便地为某平台开发？ | 库、API 封装、文档、示例、调试和构建工具 |
| Library（库） | 哪些现成代码可以直接调用？ | 函数、类、模块 |
| Framework（框架） | 整个应用应该按什么结构运行？ | 生命周期、目录结构、扩展点和大量通用功能 |

一个 SDK 可以包含多个库，也可以包含对 API 的封装；SDK 中甚至可能带一个框架。

## 开放接口与开放生态：以微信为例

> [!summary] 一句话结论
> 微信向外部开发者开放了一部分正式能力，但属于有规则、有权限边界的平台接入；开放接口不等于开放全部源码、全部用户数据或所有内部功能。

本节官方资料核对日期：2026-09-11。具体权限、申请条件和接口版本会变化，上线前还需以对应产品文档和账户实际获批状态为准。

### 1. “生态”与“对外开放”分别是什么

**生态**不是一台服务器，而是围绕平台协作的一组产品、开发者、商户、服务商与用户。例如，用户在微信里打开商家的小程序，商家经营自己的业务，开发团队制作界面和后台，支付服务处理资金流转。

**对外开放**在这里主要指：外部开发者不用进入微信内部数据库、修改微信自身代码，也能通过平台规定的接口和工具，使用被允许的能力。

像一座商业综合体：商户可以按规定入驻、使用服务窗口和公共设施，但不能因为开了一家店，就进入所有店铺的仓库、读取所有顾客资料或改动整栋楼的规则。类比用于解释权限边界，不意味着所有能力都需要同样的审批或费用。

### 2. 开放了什么，不代表什么

| 能力例子 | 外部系统可以怎样协作 | 不能据此推断 |
|---|---|---|
| 小程序开发 | 利用平台提供的组件与接口，制作自己的业务程序 | 能无限制调用手机或微信内部的所有功能 |
| 用户身份对接 | 按对应应用与授权规则获取所需身份标识 | 获得用户全部好友、聊天记录或其他未授权资料 |
| 微信支付、商家转账 | 按已开通产品和业务场景进行收款或出款 | 收款权限等于出款权限，或能任意修改用户余额 |

微信小程序官方维护了组件、接口与云开发示例，说明外部开发者可以基于其平台开发；微信支付则明确规定应用与商户号的关系、身份参数和商家转账的申请条件。[微信小程序官方示例](https://github.com/wechat-miniprogram/miniprogram-demo)、[微信支付开发参数](https://pay.wechatpay.cn/doc/v3/merchant/4013070756)、[商家转账接入准备](https://pay.wechatpay.cn/doc/v3/merchant/4013740645)

“微信生态”也不是一个一次申请就获得全部权限的账户。网站/移动应用接入、公众号与小程序、微信支付有各自的管理入口与产品规则，某些关系需要绑定，某些功能还要另行申请。是否需要认证、审核或用户明确操作，应逐项确认，不能一概而论。

### 3. 你的直播现金红包，哪些归你，哪些归微信

从职责上可以这样拆分：

- **你的课程和活动系统**：管理课程、讲师、观看资格、奖励规则、活动预算和业务记录；直播媒体能力可以另外采购或建设。
- **身份衔接**：按所选微信入口和流程，确定合法对应的用户身份或收款授权关系。
- **微信支付**：核查商户权限与资金条件，按规则处理商家转账和用户收款，向你的后台提供可核实的结果。

因此，接入微信支付不意味着整个直播平台都变成微信内部系统。业务后台可以部署在满足接入要求的自有或云端环境；它通过正式接口与微信服务协作，而不是直接登录微信的内部数据库改余额。

**商户的功能权限、用户对操作/数据的授权、服务器能否联网，是不同条件。** 其中一项成立，不能代替其他项。例如服务器能访问接口，不代表商户已获出款权限；商户获准转账，也不代表可以忽略所选模式中的用户确认或授权。[商家转账开发流程](https://pay.wechatpay.cn/doc/v3/merchant/4012715211)

具体红包接入、接口安全地址、幂等、预算和账单核对，见 [[直播平台开发前的需求、架构、成本与验收清单]]；网络访问边界见 [[防火墙与端口对外开放]]，身份与权限见 [[身份认证与授权：ACL、RBAC、MFA、OAuth、OIDC、SAML与SCIM]]。

### 4. 四个常见误解

- **开放接口 ≠ 开放源码**：知道怎样请求转账，不等于拿到了支付系统的全部实现代码。即使某个工具或示例公开了源码，也不能推断整个平台开源。
- **开放接口 ≠ 免费或无门槛**：文档能阅读，不代表所有调用者都获得权限，也不代表认证、服务或交易一定免费。
- **用户同意 ≠ 平台功能授权**：用户愿意收款，不能替代商户出款资格；反过来，商户获批也不能替代必要的用户授权。
- **手机里有按钮 ≠ 对第三方有同等接口**：用户手动能完成的动作，不一定开放给外部系统自动执行。开发方应给出对应官方接口和条件，不能把模拟点击等同于稳定的开放平台能力。

这也解释了为什么“平台开放”与“平台限制较多”可以同时成立：前者说存在合作入口，后者说入口的范围和条件。判断具体功能时，应问“哪个入口、哪个接口、什么权限、什么授权、什么限额和版本”，而不是只问整个生态开不开放。

## 常见误区

### “API 就是一个网址”

不完全正确。Web API 的 URL 只是接口约定的一部分，完整 API 还包括方法、参数、认证、返回格式和错误规则。

### “安装了 SDK 就不需要理解 API”

也不正确。SDK 简化了调用，但排查错误时仍要理解底层 API，例如限流、权限和返回字段。

### “SDK 越大越好”

不一定。大型 SDK 可能增加安装体积、依赖冲突和升级成本。简单需求有时直接调用 HTTP API 更清楚。

## 建议掌握到什么程度

初学阶段不必背诵所有 HTTP 状态码。先做到：

1. 能用一句话区分 API 和 SDK。
2. 看懂一次简单的“请求 → 响应”。
3. 知道 API Key 需要保密。
4. 遇到 SDK 报错时，知道可以去查它封装的原始 API 文档。
5. 能区分“存在开放接口”“账户获准调用”“用户完成必要授权”和“实际业务成功”。
