# 常见编程语言及其用途

> [!summary] 一句话结论
> **不存在适合所有工作的“最好语言”：JavaScript/TypeScript 擅长 Web 和跨平台应用，Python 擅长 AI、数据与自动化，Java 擅长大型企业后端，Go 擅长云服务和网络工具，Rust 擅长既要求高性能又重视内存安全的底层软件。**

一门语言能做什么，不只取决于语法，还取决于它的运行环境、库、框架、工具和人才生态。同一种应用通常也可以用多种语言完成，只是开发成本、运行性能和维护难度不同。

---

## 先看总表

| 语言 | 常见文件后缀 | 类型特点 | 常见运行方式 | 最常见的用途 |
|---|---|---|---|---|
| Go | .go | 静态类型 | 编译为本机程序 | 云服务、微服务、网络服务、CLI、DevOps 工具 |
| JavaScript（JS） | .js、.mjs | 动态类型 | 浏览器或 Node.js 等运行时 | 网页交互、Web 全栈、跨平台应用、开发工具 |
| TypeScript（TS） | .ts、.tsx | 静态类型检查 | 通常转换为 JavaScript 后执行 | 中大型前端、Node.js 后端、跨平台应用、Agent 工程 |
| Rust | .rs | 静态类型、所有权系统 | 编译为本机程序或 WebAssembly | 系统软件、高性能服务、CLI、嵌入式、安全敏感组件 |
| Java | .java | 静态类型 | 编译为字节码，在 JVM 上运行 | 企业后端、大型业务系统、Android 存量项目、大数据生态 |
| Python | .py | 动态类型 | 通常由 Python 解释器执行 | AI、数据分析、自动化、科研、脚本、Web 后端 |

这里的“静态类型”和“动态类型”暂时可以这样理解：

- **Static Typing（静态类型）**：运行程序之前，工具会检查大量类型错误；
- **Dynamic Typing（动态类型）**：程序运行到相关代码时，才完全确定值的实际类型；
- 静态类型不代表绝对安全，动态类型也不代表没有任何检查。

## 一门语言为什么会有“擅长领域”

理论上，很多通用编程语言都能实现相同的计算。现实中，开发者还要考虑以下因素。

### 1. 运行环境

浏览器原生执行的主要脚本语言是 JavaScript，因此网页前端天然以 JavaScript/TypeScript 为中心。

操作系统、嵌入式设备和高性能组件通常需要本机机器码，因此 C、C++、Rust 更常见。

### 2. 生态系统

**Ecosystem（生态系统）**包括：

- 第三方库；
- Web 或 AI 框架；
- 包管理器；
- 编辑器和调试工具；
- 部署平台；
- 教程、社区与开发者人才。

Python 在 AI 领域强大，不只是因为语法简单，更因为 NumPy、PyTorch、Pandas 等生态已经积累了大量工具。

### 3. 性能和资源消耗

有的任务重视快速开发，有的任务重视执行速度、内存占用或启动速度。例如：

- 一次性整理表格，开发效率通常比极致运行速度更重要；
- 数据库、浏览器引擎或游戏引擎每秒要处理大量工作，性能非常重要；
- 小型容器和命令行工具还可能关心程序体积与启动时间。

### 4. 安全与维护

语言可以帮助开发者提前阻止不同类型的错误：

- TypeScript、Java、Go 用静态类型发现许多类型不匹配；
- Rust 进一步用所有权和借用规则阻止大量内存错误与数据竞争；
- Python、JavaScript 更灵活，大型项目通常需要测试、类型标注和运行时数据校验来加强约束。

### 5. 团队与已有系统

成熟团队很少只因为另一门语言“看起来更先进”就重写系统。已有代码、团队经验、部署平台和维护成本往往比语言排行榜更重要。

## Go：云服务、网络程序和命令行工具

**Go** 读作“够”。它的正式名称就是 Go；**Golang** 是为了便于搜索而常用的叫法，不是另一门语言。

Go 是静态类型、编译型语言，通常直接编译成本机可以运行的程序。

### Go 通常用来做什么

- Web 后端和 API 服务；
- 微服务；
- 云原生基础设施；
- 网络服务器、代理和网关；
- CLI（Command-Line Interface，命令行界面）工具；
- DevOps（开发与运维协作）和平台工程工具；
- 需要处理大量并发网络请求的服务。

Docker、Kubernetes 等云原生项目都大量使用 Go。

### 为什么这些领域喜欢 Go

1. **部署方便**：通常可以生成一个独立可执行文件；
2. **启动较快、资源开销可控**；
3. **并发语法简洁**：goroutine 和 channel 便于组织大量并发任务；
4. **标准库实用**：网络、HTTP、测试等能力比较完整；
5. **语言设计相对克制**：大型团队更容易形成统一写法。

**Concurrency（并发）**不是“所有代码同时执行”的同义词，而是程序能组织和推进多个任务。例如服务器可以在等待一个网络响应时处理其他请求。

### 一个极简 Go 例子

~~~go
package main

import "fmt"

func main() {
    fmt.Println("你好，Go")
}
~~~

通常使用 Go 工具链把它编译成可执行程序，再运行。

### Go 不一定最适合什么

- 浏览器网页界面；
- 以深度学习研究为主的项目；
- 对硬件和内存布局需要极细控制的底层核心；
- 高度依赖复杂桌面 UI 生态的应用。

这不表示 Go 完全做不了，而是这些领域通常有生态更成熟的选择。

### Go 常用工具

| 工具/概念 | 用途 |
|---|---|
| go build | 编译程序 |
| go test | 运行测试 |
| go mod | 管理项目模块与依赖 |
| gofmt | 统一格式化代码 |

## JavaScript：浏览器中的核心编程语言

**JavaScript（简称 JS）**读作“Java Script”。它和 Java 名字相似，但不是 Java 的简化版，两者是不同语言。

### JavaScript 通常用来做什么

- 网页按钮、表单、动画和交互；
- React、Vue 等 Web 前端应用；
- 通过 [[Node.js与pnpm|Node.js]] 开发后端和脚本；
- 浏览器扩展；
- Electron 桌面应用；
- React Native 等跨平台移动应用；
- 构建工具、编辑器插件和自动化脚本；
- Serverless（无服务器）函数和边缘函数。

### JavaScript 为什么特别适合 Web

浏览器直接提供页面结构访问、用户输入事件、网络请求、本地存储、图形和音视频等 API。JavaScript 可以调用它们，让 [[HTML]] 和 [[CSS]] 描述的页面产生行为。

~~~mermaid
flowchart LR
    HTML["HTML：结构"] --> Page["网页"]
    CSS["CSS：样式"] --> Page
    JS["JavaScript：行为"] --> Page
~~~

### Node.js 改变了什么

以前 JavaScript 主要在浏览器里运行。Node.js 把 JavaScript 运行时带到服务器和本地电脑，使它还可以：

- 启动 Web 服务器；
- 读写文件；
- 连接数据库；
- 编写命令行工具；
- 运行 Webpack 等前端构建工具。

因此 JavaScript 可以覆盖“浏览器前端 + 服务器后端”，常被称为 Web 全栈语言。

### JavaScript 的优势

- Web 开发不可绕开的核心语言；
- 生态庞大，库和工具非常多；
- 从页面到后端可以使用同一门语言；
- 适合快速制作交互原型；
- 异步 I/O 适合许多网络应用。

### JavaScript 的注意点

- 动态类型可能让部分错误到运行时才暴露；
- 语言中存在历史兼容行为，初学时有些规则不直观；
- npm 生态庞大，但依赖和工具选择也容易令人困惑；
- 单个 JavaScript 主线程不适合直接承担长时间 CPU 密集计算，需要 Worker、子进程或原生组件等方案。

## TypeScript：更适合维护中大型 JavaScript 项目

**TypeScript（简称 TS）**读作“Type Script”，可以先记成：

~~~text
TypeScript = JavaScript + 类型语法 + 静态类型检查
~~~

TS 代码通常先经过检查和转换，最后以 JavaScript 形式交给浏览器或 Node.js 执行。详细原理见 [[TypeScript与JavaScript]]。

### TypeScript 通常用来做什么

它能参与 JavaScript 能做的大部分项目，尤其常见于：

- 中大型 Web 前端；
- Node.js 后端；
- 全栈 Web 框架；
- 跨平台桌面和移动应用；
- SDK 和公共组件库；
- 编辑器、开发工具和自动化平台；
- AI Agent、MCP 服务和工具编排系统。

### 为什么大型项目更喜欢 TypeScript

~~~ts
type User = {
  id: number
  name: string
}

function greet(user: User) {
  return "你好，" + user.name
}
~~~

编辑器可以提前发现属性拼写错误、参数类型错误和修改接口后受影响的位置。项目越大、协作人数越多，这类帮助越明显。

### TypeScript 不能自动解决什么

- 不能自动保证业务逻辑正确；
- 类型通常在生成 JavaScript 时被擦除；
- 不能自动验证网络和数据库传来的真实数据；
- 不能代替测试、错误处理和安全检查；
- 它通常不会让程序运行速度自动变快。

### 应该先学 JS 还是 TS

先掌握 JavaScript 的变量、函数、对象、数组、异步操作和模块，再学习 TypeScript 类型系统。只背 TS 类型而不了解 JS 运行行为，会很难排查实际错误。

## Rust：高性能与内存安全

**Rust** 读作“拉斯特”，意思是“锈”。它是静态类型、编译型的系统编程语言。

**Systems Programming（系统编程）**通常指更接近操作系统、硬件、运行时和性能核心的开发，开发者需要关心内存、线程、文件、网络和资源生命周期。

### Rust 通常用来做什么

- 操作系统组件和系统工具；
- 高性能网络服务；
- 数据库、存储引擎与解析器；
- 安全敏感的基础组件；
- CLI 工具；
- 嵌入式软件；
- 游戏引擎或高性能游戏组件；
- WebAssembly（简称 Wasm）模块；
- 给 Python、JavaScript 等语言提供的原生高性能扩展。

### Rust 的核心特点：所有权

Rust 使用 **Ownership（所有权）**、**Borrowing（借用）**和生命周期规则管理内存。

它希望在编译阶段阻止：

- 使用已经释放的内存；
- 同一块可变数据被不安全地同时访问；
- 许多空指针和悬垂引用问题；
- 一部分多线程数据竞争。

~~~text
传统思路：运行时垃圾回收，或由开发者手动管理内存
Rust 思路：让编译器检查资源的所有权和借用关系
~~~

Rust 通常不需要 Java、Go 那样的垃圾回收器，也不要求开发者像 C 那样到处手动释放内存。

### Rust 的优势

- 接近 C/C++ 的性能目标；
- 在不使用不安全代码的正常范围内提供很强的内存安全保证；
- 适合控制内存布局和资源生命周期；
- Cargo 集成构建、依赖、测试和发布，开发工具体验较统一。

### Rust 的学习难点

- 所有权、借用和生命周期需要新的思维方式；
- 编译器规则严格，初期经常需要理解错误提示；
- 某些领域的 GUI 或企业框架生态不如 Java、JavaScript 成熟；
- 对只写简单业务表单的初学者，投入可能大于收益。

Rust 很强，但通常不建议把它作为完全没有编程基础时必须学习的第一门语言。

## Java：大型企业后端与 JVM 生态

**Java** 读作“爪哇”。Java 是静态类型语言，源码通常先编译为 **Bytecode（字节码）**，再交给 **JVM（Java Virtual Machine，Java 虚拟机）**运行。

~~~mermaid
flowchart LR
    Source[".java 源码"] --> Compiler["Java 编译器"]
    Compiler --> Bytecode[".class 字节码"]
    Bytecode --> JVM["JVM"]
    JVM --> OS["Windows / Linux / macOS"]
~~~

### Java 通常用来做什么

- 银行、电商、物流等大型企业后端；
- 订单、支付、账户和管理系统；
- Spring/Spring Boot 微服务；
- 大型组织的长期业务平台；
- Android 应用的存量项目及部分新项目；
- Hadoop 等大数据生态中的系统；
- 需要成熟监控、诊断和工程规范的服务器软件。

### 为什么企业后端大量使用 Java

- JVM 跨平台且经过长期生产验证；
- 性能、稳定性和运行时诊断能力成熟；
- Spring 等企业框架生态完整；
- 数据库、消息队列和监控组件支持丰富；
- 静态类型适合多人协作和长期维护；
- 大量已有系统、开发者和组织经验可以复用。

### Java 的注意点

- 相比 Python、JavaScript，很多代码更正式、结构更重；
- JVM 应用通常比小型本机程序需要更多运行时资源；
- 生态庞大，Spring、Maven、Gradle、JVM 等概念会带来学习量；
- Android 现代开发中 Kotlin 很常见，但 Java 仍有大量现有代码和库。

### Java 与 JavaScript 没有继承关系

~~~text
Java ≠ JavaScript
~~~

二者的类型系统、运行环境、主要生态和用途都不同。名字相似是历史命名原因，不能理解为“JavaScript 是脚本版 Java”。

### Java 常用工具与框架

| 工具/框架 | 用途 |
|---|---|
| JVM | 运行 Java 字节码 |
| Maven / Gradle | 构建项目和管理依赖 |
| Spring Boot | 开发 Web 后端和微服务 |
| JUnit | 编写自动化测试 |

## Python：AI、数据、科研与自动化

**Python** 读作“派森”。它是动态类型语言，以语法直观、库丰富和开发速度快著称。

### Python 通常用来做什么

- 机器学习、深度学习和大语言模型应用；
- 数据清洗、分析和可视化；
- 科学计算与科研实验；
- 自动处理文件、表格和图片；
- 爬虫和测试脚本；
- 运维与办公自动化；
- 使用 [[Django]]、FastAPI、Flask 等开发 Web 后端；
- 教学、算法练习和快速原型。

### 为什么 AI 领域常用 Python

Python 本身不一定执行所有重计算。很多库的核心计算由 C、C++、CUDA 等高性能代码完成，Python 负责提供更容易使用的接口和组织逻辑。

~~~mermaid
flowchart LR
    Python["Python 代码：组织实验和调用接口"] --> Library["PyTorch / NumPy 等库"]
    Library --> Native["C / C++ / CUDA 等高性能核心"]
    Native --> Hardware["CPU / GPU"]
~~~

因此不能简单理解为：“Python 自己执行得不如 Rust 快，所以不适合 AI。”在 AI 开发中，开发生态和底层加速库同样重要。

### Python 的优势

- 语法相对容易阅读，适合初学者；
- 编写同一业务通常需要的代码较少；
- AI、数据、科研和自动化库非常丰富；
- 交互式环境适合边实验边观察结果；
- 很适合把多个系统快速连接起来。

### Python 的注意点

- 纯 Python 的 CPU 密集代码通常不以极致性能见长；
- 动态类型可能让部分错误在运行时出现；
- 项目需要正确管理 [[Anaconda与Python环境管理|虚拟环境和依赖版本]]；
- 把脚本发展成大型长期系统时，也需要类型标注、测试和清晰架构；
- 桌面应用、移动端和浏览器前端通常不是它最主流的领域。

### 一个极简 Python 例子

~~~python
names = ["小明", "小红"]

for name in names:
    print("你好，" + name)
~~~

Python 用缩进表示代码块，不使用大括号包住循环体。

## 除此之外还有哪些主流语言

“主流”没有永久统一的排行榜：Web、手机、游戏、科研和嵌入式领域各有自己的主力语言。除前面的六种外，下面这些也很常见。

| 语言 | 主要领域 | 一句话特点 |
|---|---|---|
| C | 操作系统、驱动、嵌入式 | 接近硬件、运行开销小，但需要谨慎管理内存 |
| C++ | 游戏引擎、浏览器、数据库、高性能程序 | 在 C 的底层能力上增加抽象能力，功能强但复杂 |
| C# | .NET 后端、Windows、Unity 游戏 | 微软 .NET 生态的主力语言 |
| Kotlin | Android、JVM 后端 | 与 Java 生态兼容，语法更现代简洁 |
| Swift | iPhone、iPad、Mac 应用 | Apple 平台的现代主力语言 |
| PHP | 网站后端、内容管理系统 | 为 Web 服务端开发积累了庞大生态 |
| Dart | Flutter 跨平台应用 | 用一套代码开发多端界面 |
| Ruby | Web 后端、脚本 | 强调开发者体验，Ruby on Rails 影响很大 |
| R | 统计分析、学术研究、数据可视化 | 面向统计计算和数据分析 |
| SQL | 关系型数据库查询 | 描述想查什么，不是普通通用编程语言 |
| Shell | 命令编排、运维自动化 | 把操作系统命令连接成脚本 |
| Lua | 游戏脚本、嵌入式扩展 | 体积小，容易嵌入其他程序 |
| Scala | JVM、大数据、后端 | 结合面向对象与函数式编程 |

### C：操作系统和嵌入式基础

**C** 不是缩写，它是一门历史悠久的通用编程语言。常见用途包括：

- 操作系统内核；
- 硬件驱动；
- 单片机和嵌入式设备；
- 编程语言运行时；
- 对资源占用要求严格的库。

C 允许开发者直接处理指针、内存地址和硬件资源，因此自由度和性能控制很强。但越接近底层，开发者越需要自己防止越界访问、悬垂指针和内存泄漏。

### C++：游戏引擎与大型高性能软件

**C++** 读作“C Plus Plus（C 加加）”。它常见于：

- Unreal Engine 等游戏和游戏引擎；
- 浏览器引擎；
- 数据库与存储系统；
- 图形、音视频和实时处理；
- 桌面软件；
- 高频交易和其他低延迟系统。

C++ 能进行底层控制，也提供类、模板、泛型和现代资源管理工具。它的能力非常广，但语言规则和历史兼容内容也很多，学习与大型工程管理难度较高。

### C#：.NET、企业应用与 Unity

**C#（C Sharp，读作“C 夏普”）**是 .NET 生态的重要语言，常用于：

- ASP.NET Core Web 后端；
- 企业管理系统；
- Windows 桌面应用；
- Unity 游戏开发；
- 跨平台服务和工具。

C# 与 Java 都属于静态类型、带垃圾回收、企业生态成熟的语言，但分别主要建立在 .NET 与 JVM 生态上。

### Kotlin：现代 Android 与 JVM 开发

**Kotlin** 读作“科特林”，常用于：

- Android 原生应用；
- JVM Web 后端；
- 与现有 Java 项目混合开发；
- Kotlin Multiplatform 跨平台项目。

Kotlin 能调用大量 Java 库，并改进了空值处理、数据类和协程等开发体验。它不是“Java 的新版本”，而是一门可以与 Java 互操作的独立语言。

### Swift：Apple 平台原生应用

**Swift** 读作“斯威夫特”，主要用于：

- iPhone 和 iPad 应用；
- macOS 应用；
- watchOS 与 tvOS 应用；
- 部分服务器端开发。

如果目标是 Apple 平台原生开发，Swift 通常是优先学习的语言；旧项目中也可能遇到 Objective-C。

### PHP：大量网站的服务端语言

**PHP（PHP: Hypertext Preprocessor，超文本预处理器）**主要用于 Web 后端。常见场景包括：

- 内容网站和企业官网；
- WordPress 网站；
- 电商和管理后台；
- Laravel、Symfony 等框架项目。

PHP 部署广泛、Web 生态成熟。它不只适合“小网站”，但新项目是否选择它仍取决于团队和现有技术栈。

### Dart：Flutter 跨平台界面

**Dart** 读作“达特”，现在最常与 Flutter 一起出现。Flutter 可以用一套 Dart 代码构建 Android、iOS、Web 和桌面界面。

Dart 的主流影响力与 Flutter 生态高度相关。如果不做 Flutter，通常不必把 Dart 放在第一批学习语言中。

### Ruby：强调开发效率的 Web 语言

**Ruby** 读作“如比”，以灵活、易读和强调开发者体验著称。最知名的应用是 Ruby on Rails Web 框架。

Ruby 仍用于 Web 产品、内部工具和自动化，但目前不同地区的岗位和新项目数量差异较大，选择前应观察目标团队的实际技术栈。

### R：统计分析与数据可视化

**R** 主要面向：

- 统计建模；
- 学术研究；
- 生物信息学；
- 数据分析与可视化；
- 报告生成。

Python 的数据生态覆盖更广，R 则在统计分析和部分科研社区中拥有深厚积累。两者可以配合使用。

### SQL：和数据库交流的查询语言

**SQL（Structured Query Language，结构化查询语言）**读作“S-Q-L”或“sequel”，用于关系型数据库：

- 查询数据；
- 插入、修改和删除数据；
- 创建表与索引；
- 统计、分组和关联多张表；
- 管理部分权限和事务。

SQL 通常被称为领域专用语言，而不是 Java、Python 那样的通用编程语言。做后端、数据分析或数据工程时，无论主力语言是什么，SQL 都很重要。可结合 [[ORM]] 理解。

### Shell：连接命令的自动化脚本

Shell 不是单独某一门语言，而是一类命令解释器及其脚本语言，例如 Bash 和 PowerShell。常用于：

- 批量运行命令；
- 构建和部署；
- 服务器运维；
- 文件整理；
- CI/CD 自动化。

Shell 很适合“把几个现有程序串起来”，但复杂业务逻辑变大后，Python、Go 等语言通常更容易测试和维护。详见 [[CMD、Bash与PowerShell]]。

### Lua：嵌入其他程序的小型脚本语言

**Lua** 读作“露阿”，特点是实现小巧、容易嵌入，常见于：

- 游戏玩法和插件脚本；
- Nginx/OpenResty 扩展；
- 应用配置和自动化；
- 嵌入式设备。

很多用户不会直接启动一个大型 Lua 系统，而是在某个宿主程序中用 Lua 定义可变行为。

### Scala：JVM 与大数据生态

**Scala** 来自“Scalable Language（可扩展语言）”这个名字，运行在 JVM 上，结合面向对象与函数式编程，常见于：

- Apache Spark 数据处理；
- 数据平台；
- JVM 后端服务；
- 强调函数式编程的系统。

Scala 表达能力很强，但语言与构建生态的学习量也比较大。只为了普通 Web 后端，Java、Kotlin 等选择可能更直接。

### 还有一些领域型主流语言

- **Objective-C**：Apple 平台旧项目中常见；
- **MATLAB**：工程计算、信号处理和控制系统；
- **Julia**：科学计算与数值计算；
- **Elixir/Erlang**：高并发、容错通信系统；
- **Groovy**：JVM 脚本以及部分 Gradle/Jenkins 配置；
- **Solidity**：以太坊等智能合约；
- **SAS**：部分金融、医药与统计分析环境。

是否“主流”必须带上领域和地区：一种语言可能在互联网前端很少见，却在芯片、银行、科研或游戏行业非常重要。

## 它们在同一个系统中可以怎样合作

大型软件经常是多语言系统，并不要求所有部分使用同一种语言。

以 AI 网站为例：

~~~mermaid
flowchart LR
    Browser["浏览器界面<br/>TypeScript"] --> API["业务 API<br/>Java / Go / TypeScript"]
    API --> AI["模型与数据处理<br/>Python"]
    API --> Perf["高性能原生组件<br/>Rust"]
    API --> DB["数据库<br/>SQL"]
~~~

可能的分工是：

- TypeScript 负责浏览器界面；
- Java 或 Go 负责订单、用户、权限等业务服务；
- Python 负责模型推理流程和数据分析；
- Rust 负责沙箱、解析器或高性能组件；
- 各部分通过 [[SDK与API|API]]、消息队列或文件通信。

这也解释了为什么一个 GitHub 仓库里可能同时出现 .ts、.py 和 .rs 文件。

## Go、Java、Rust 怎样区别

三者都可以开发后端和命令行工具，但设计重点不同。

| 对比 | Go | Java | Rust |
|---|---|---|---|
| 主要定位印象 | 简洁的云服务与工具 | 成熟的大型业务系统 | 高性能、安全的系统组件 |
| 运行方式 | 编译为本机程序 | JVM 字节码 | 编译为本机程序 |
| 内存管理 | 垃圾回收 | 垃圾回收 | 所有权为主，无常规 GC |
| 并发特色 | goroutine/channel 简洁 | 线程、线程池、虚拟线程及成熟框架 | 编译期安全约束强，异步生态可选 |
| 学习难度 | 相对平缓 | 概念和框架较多 | 所有权使初期较陡 |
| 常见优势 | 部署、并发、工具链简洁 | 生态、长期维护、企业能力 | 性能、内存安全、底层控制 |

如果只是开发普通业务 API，三者都能做到。真正的选择还要看团队、框架、部署环境和已有系统。

## JavaScript、TypeScript、Python 怎样区别

| 对比 | JavaScript | TypeScript | Python |
|---|---|---|---|
| 浏览器前端 | 核心语言 | 大型项目常用，最终通常生成 JS | 非主流 |
| Node.js 后端 | 常见 | 中大型项目更常见 | 不适用 Node.js，但有自己的后端框架 |
| AI 与数据 | 有相关库，但不是主流中心 | 适合 AI 产品界面和工具层 | 研究、训练和数据处理主流 |
| 类型 | 动态 | 开发阶段静态检查，运行行为基于 JS | 动态，可加类型标注 |
| 初学体验 | 能立即做网页，但有历史细节 | 需同时理解 JS 与类型 | 语法直观，适合算法和自动化入门 |

如果目标是做网页，先学 JavaScript，再学 TypeScript；如果目标是 AI、数据或自动化，可以先学 Python。

## “编译型语言”和“解释型语言”不要分得过死

初学教程常说：

~~~text
Go、Rust、Java：编译型
JavaScript、Python：解释型
~~~

这是方便入门的简化，但现代实现更复杂：

- Go、Rust 通常提前编译为本机机器码；
- Java 先编译成字节码，JVM 运行时还可能即时编译；
- JavaScript 引擎通常会解释并使用 JIT（Just-In-Time，即时编译）优化热点代码；
- Python 源码通常先转为字节码，再由解释器执行；不同 Python 实现也可能采用不同技术；
- TypeScript 的类型通常被移除，生成 JavaScript 后再运行。

因此更实用的问题是：

- 最终由谁执行？
- 部署时需要什么运行时？
- 类型在什么时候检查？
- 性能关键代码怎样优化？

## 常见误区

### 误区 1：性能最高的语言一定最好

运行速度只是成本之一。一个每天只执行一分钟的内部工具，开发者多花两个月优化，可能比节省的机器费用贵得多。

### 误区 2：Python 做 AI，所以 AI 的所有代码都是 Python

Python 经常负责调用和组织，底层张量计算、GPU 内核和推理引擎可能由 C++、CUDA、Rust 等实现。

### 误区 3：TypeScript 是独立于 JavaScript 的全新运行平台

TS 通常转成 JS 后运行。学 TS 不能跳过 JS 的运行机制。

### 误区 4：JavaScript 和 Java 是同一种语言

它们只是名字相似。JavaScript 不是“轻量版 Java”。

### 误区 5：Rust 会自动让所有程序都更快、更安全

Rust 能阻止许多内存错误，但算法、业务逻辑、不安全代码、外部依赖和配置仍可能出错。性能也取决于具体实现。

### 误区 6：Go 的并发语法意味着所有任务都会自动并行

并发是组织多个任务，是否并行还取决于 CPU、运行时调度和任务类型。

### 误区 7：必须把六种语言全部学会才能当程序员

大多数开发者有一两门主力语言，再根据工作需要阅读或使用其他语言。基础概念通常可以迁移。

## 对初学者的学习路线建议

### 路线 A：想做网页和 App

~~~text
HTML → CSS → JavaScript → TypeScript
→ 前端框架 → Node.js/后端/API → 数据库
~~~

相关笔记：[[HTML]]、[[CSS]]、[[TypeScript与JavaScript]]、[[Node.js与pnpm]]、[[SDK与API]]。

### 路线 B：想学 AI、数据和自动化

~~~text
Python 基础 → 文件与数据处理 → NumPy/Pandas
→ 机器学习基础 → PyTorch/模型 API → RAG/Agent
~~~

相关笔记：[[LangChain]]、[[RAG、Naive RAG与GraphRAG]]、[[MCP模型上下文协议]]。

### 路线 C：想做企业后端

~~~text
一门基础语言 → HTTP/API → SQL/数据库 → Java + Spring Boot
→ 缓存、消息队列、测试、部署与分布式系统
~~~

如果团队使用 Go、Python 或 TypeScript，也可以沿相同的后端基础路线学习，语言只是实现工具之一。

### 路线 D：想做云原生和基础设施

~~~text
Linux/Shell → 网络与 HTTP → Go
→ 容器与 Kubernetes → 可观测性 → 分布式系统
~~~

相关笔记：[[CMD、Bash与PowerShell]]、[[TCP、HTTP、HTTPS与WebSocket]]、[[状态机与幂等性]]。

### 路线 E：想做系统与高性能开发

~~~text
编程基础 → 数据结构 → 操作系统与计算机组成
→ C 基础概念 → Rust → 并发、网络与性能分析
~~~

不一定要先精通 C 才能学 Rust，但了解栈、堆、指针、内存和线程会明显降低理解难度。

## 如果现在还不知道方向

可以先选一门反馈快的语言建立基础：

- 想尽快写自动化、处理数据或接触 AI：选 **Python**；
- 想做网页、可视化界面或全栈产品：选 **JavaScript**，随后学 **TypeScript**；
- 已确定学校或工作使用 Java：直接选 **Java**；
- 已确定目标是云服务、网络工具：可以选 **Go**；
- 已有基础并明确想做系统、安全或高性能组件：再重点学 **Rust**。

第一门语言真正要掌握的是可迁移的基础：

- 变量和数据类型；
- 条件与循环；
- 函数；
- 数组、列表、映射和对象；
- 模块与包；
- 错误处理；
- 文件和网络；
- 调试与测试；
- Git 与命令行；
- 数据结构和基本算法。

换语言时，很多概念仍然适用，只是语法和工具不同。
