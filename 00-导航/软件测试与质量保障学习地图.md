# 软件测试与质量保障学习地图

> [!summary] 一句话说明
> **这条路线把“理解系统怎样工作”连接到“设计检查、执行检查、分析证据和说明风险”，覆盖基础测试、工具、AI 与设备专项。**先按业务问题学习，再选择对应工具。

## 从哪里开始

初学者先读 [[全量测试、回归测试与测试分层]]，分清测试范围、层级、方法和执行方式。随后按下表顺序学习，主线可以一直采用“登录—找课程—报名—观看—查看记录”。示例中的账号、订单、金额和设备均为教学场景，不是已经完成的实际项目验证。

## AI 测试路线

1. [[AI评测指标：准确率、精确率、召回率、F1与检索排名]]：先能手算指标，明确分母和适用范围。
2. [[Agent评测：上下文成本、轨迹与独立验收]]：评测集、意图、拒识、槽位、多轮、裁判、Ragas/DeepEval/LangSmith 和回归。
3. [[RAG、Naive RAG与GraphRAG]]：逐层检查资料、分块、检索、重排、组装和回答。
4. [[向量引擎、向量数据库与相似度检索]]：Milvus/Chroma 的数据组织、写入查询与更新测试。
5. [[Coze扣子：智能体搭建、工作流与平台测试]] 与 [[Dify：可视化AI应用、知识库与工作流平台]]：检查平台节点与发布应用。
6. [[SSE与流式响应]]：内容完整性、首 Token、取消、重连和用量对账。
7. [[大模型从数据、Token到训练与本地部署]]：Hugging Face、SFT、LoRA、数据划分和训练后评测。

## 一套可逐步完成的练习

| 阶段 | 产物 | 自查标准 |
|---|---|---|
| 理解需求 | 5 条明确规则、待确认问题 | 规则有输入、条件与结果 |
| 设计 | 需求—用例矩阵、正常/异常用例 | 每条预期有依据，而非只写“正常” |
| 执行 | 版本/环境记录、结果、缺陷 | 失败、阻塞、未执行分开 |
| 自动化 | 可重复用例与数据准备/清理 | 不依赖上一条成功，无真实副作用 |
| 专项 | 一个权限矩阵或性能小实验 | 目标、口径、条件和原始证据明确 |
| AI | 小规模标注题集和逐题结果 | 评测标准、模型/资料版本和成本可追踪 |
| 复盘 | 一页报告 | 能说明验证了什么、没有验证什么 |

这是一条学习路线，不是要求一次安装所有工具。通用方法学会后，选一个接口工具、一个测试框架先完成闭环，其他工具再按项目需要对照学习。
